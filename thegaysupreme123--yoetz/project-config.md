# AGENTS.md

Short contract for coding agents and humans editing this repository. Human process detail lives in
[`CONTRIBUTING.md`](CONTRIBUTING.md) — follow that for intake, design gates, and review disposition.
`CLAUDE.md` is an alias for this file.

## Authority order

For public behavior, resolve in this order:

1. [`docs/adr/`](docs/adr/) — architecture decisions;
2. [`docs/INTERFACES.md`](docs/INTERFACES.md) — shared names and trust boundaries;
3. the code and the tests that lock it.

For exact wire shape and byte identity, [`schemas/`](schemas/) and [`fixtures/`](fixtures/) win over
prose. Start at [`docs/architecture.md`](docs/architecture.md) to find the owning module.

Do not invent behavior that contradicts those authorities. When behavior changes, update the ADR or
affected `docs/` page in the same change.

## How it works

Hosts (Codex, Claude Code, Cursor) reach Yoetz through hook events, MCP tools, and the CLI. Every
request goes to one singleton local service (`src/yoetz/service/`, Unix-socket control channel).
The kernel (`src/yoetz/kernel/`) is event-sourced: requests become recorded events in a SQLite
ledger, projections derive state from those events, and deterministic checks plus optional advisory
semantic review produce receipts. Adapters (`src/yoetz/adapters/`) hold every host, git, SQLite,
and provider boundary. `src/yoetz/resources/` is a generated byte-mirror of the repo-root
`schemas/`, `fixtures/`, `guidance/`, `migrations/`, and `support/` trees, converged by the resource
ripple below. Full map: [`docs/architecture.md`](docs/architecture.md); shared vocabulary:
[`docs/INTERFACES.md`](docs/INTERFACES.md).

1. Search issues/PRs for duplicates.

## Ways to hurt yourself

1. **The live install is real.** The user data directory (`yoetz.config.paths.state_dir()`; on
   macOS `~/Library/Application Support/yoetz/`) holds the maintainer's vault, catalog, task
   ledgers, and the running service's singleton lock. Never start a service, run tests, or open a
   ledger read-write against it. For realistic data, copy into an isolated state directory:
   SQLite files travel with their `-wal`/`-shm` siblings (a live copy without them is a corrupt
   copy); the copy must sit in a symlink-free, mode-0700 directory — not `/tmp`, which macOS
   resolves through a symlink and the runtime refuses as `path_contains_symlink`. Copy in, never
   symlink, never copy back. Copying vault material needs maintainer sign-off first.
   For anything that needs an installed launcher, a running service, a host registration, or an
   upgrade path, provision an independent test instance instead
   (`scripts/provision_test_instance.py`, [`docs/runbooks/test-instances.md`](docs/runbooks/test-instances.md),
   ADR-028): it builds a wheel from the exact revision, installs it into its own runtime, and pins
   that runtime to its own root, service, and vault, so a dropped `YOETZ_ISOLATED_ROOT`, a hook,
   or a `PATH` that lists the test runtime first can no longer reach the live singleton. Setting
   `YOETZ_ISOLATED_ROOT` alone (ADR-026) still isolates an explicitly exported process tree but
   not a bare launcher; a bare `yoetz` resolved through `PATH` in a host registration is how the
   live service got superseded by a test build (issue #604). Register hosts with absolute
   launcher paths.
2. **Never kill the service by pattern.** `pkill -f yoetz`, `pgrep | kill`, or killing a PID matched
   on a path also hits the user's real service and the hook/bridge processes, whose argv carries
   this checkout's path. Stop only a PID you spawned, or use the sanctioned path: `yoetz service
   restart` supersedes an incompatible holder through the lock stamp, and `yoetz service status`
   reports the holder.
3. **Git worktrees have sharp edges.** Always `uv run` inside the worktree: bare `pytest` from the
   primary checkout's `.venv` resolves `yoetz` to the primary checkout and silently tests the wrong
   tree. `yoetz state capture` requires `.git` to be a directory, so it rejects a worktree
   (`UNSAFE_ROOT`); run `tests/packaging/` from the primary checkout. `npx --no-install pyright`
   needs `node_modules`, which a fresh worktree lacks — run the primary checkout's
   `node_modules/.bin/pyright` against the worktree. Keep worktree paths short: tests bind Unix
   sockets beneath the working tree, and a long path fails as `endpoint_unsafe`
   (`AF_UNIX path too long`).
4. **Edit sources, not mirrors.** `guidance/`, `schemas/`, `migrations/`, `support/`, and
   `skills/codex/` at the repo root are the sources; `src/yoetz/resources/` and the committed
   `.agents/` trees are generated. `scripts/sync_resource_ripple.py` converges the package mirror
   but does not re-render `.agents/`; `tests/packaging/test_committed_*_tree.py` gates both.
