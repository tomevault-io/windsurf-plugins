# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Autonomous YouTube content pipeline. Daemon (`agent.py`) runs 24/7, triggers per scheduled hour, produces full videos (script → TTS → stock clips → montage → thumbnail → upload) with zero human input. Controlled live via Telegram bot.

## Run / Setup

### First time (new user)

**Quick Start (recommended — no cloning needed):**
```bash
pip install uv                                                    # fast installer (one-time)
uv tool install git+https://github.com/metiu1/tube-assistant.git
tube-assistant             # interactive menu — pick Setup wizard first
```

**From source (git clone):**
```powershell
.\installa.bat                  # uv tool install -e . + instructions
tube-assistant onboard          # TUI wizard: AI service → Pexels → clip source → Telegram → channel setup
tube-assistant start            # start daemon
```
The wizard writes `.env`, `preferenze_video.json`, `memoria_lungo_termine.json`, `credentials.json` to the workspace. No manual file editing needed.

### Already configured
```powershell
python agent.py      # daemon (production)
python main.py       # one-shot pipeline (no scheduler, no Telegram, no checkpoint)
.\avvia_agente.bat   # background (start /min tube-assistant start)
```

Tests: `python -m unittest discover -s tests` (also run by `.github/workflows/tests.yml`).
`tests/test_runtime_safety.py` covers state/Telegram/AI-fallback; `tests/test_regressioni.py`
covers scheduling, preferences parsing, YouTube API limits, captions, clip cache, audio
chunking and real ffmpeg renders (render tests self-skip when ffmpeg is absent).
`tests/test_regressioni_qualita.py` covers the output quality of a finished video:
delivery loudness/format, clip pool size vs segment count, stock-clip relevance,
script length, one-shot captions, render progress and thumbnail safe area.
`tests/test_video_ai.py` covers AI video generation: the three `VIDEO_SOURCE` modes,
the spend cap, the fallback to Pexels, provider response parsing and the settings screen.
`tests/test_regressioni_e2e.py` covers the CLI/workspace layer end to end, including
packaging: the wheel must bundle `assets/music` and `template/.env.example` or a
`uv tool install` user gets silent videos and an empty `.env`.

Requires: FFmpeg in PATH (MoviePy), `credentials.json` (Google OAuth desktop), `.env` with AI service vars, `PEXELS_API_KEY`, Telegram bot token. All populated by `wizard.py`.
The `.env` template lives at `youtube_ai_agent/template/.env.example` (bundled in the wheel);
`_workspace.scaffold` copies it, plus `assets/music`, into a fresh workspace.

### AI service (`AI_SERVICE` in `.env`)
15 providers (`openrouter`, `openai`, `anthropic`, `gemini`, `mistral`, `groq`, `deepseek`,
`xai`, `cohere`, `together`, `perplexity`, `fireworks`, `azure_openai`, `ollama_cloud`,
`ollama_local`). The value → key-variable map is `AI_KEY_BY_SERVICE` in `moduli/preflight.py`;
the README table is the user-facing copy. Only OpenRouter and Ollama need no extra SDK.

`ai_client.py:_primary()` routes to the configured service; `_fallback()` tries a secondary on failure.

## Architecture

Pipeline = 7 stages, each a module in `moduli/`. `agent.py:run_pipeline` orchestrates; `main.py` is a stripped one-shot variant.

| Stage | Module | Role |
|---|---|---|
| Analytics | `analytics.py` | Reads YouTube channel performance via Data API |
| Strategy | `strategia.py` | Maps performance → tone/mood/length hints |
| Brain | `cervello.py` → `ai_client.py` | Topic + JSON script (Ollama Cloud primary, OpenRouter fallback) |
| Audio | `audio.py` | edge-tts → `output/narration.mp3` |
| Clips | `asset.py` → `video_ai.py` | Pexels search/download → `cache/pexels/`, plus AI-generated clips → `cache/ai_video/` |
| Montage | `montaggio.py` | MoviePy concat + audio sync → `output/output_finale.mp4` |
| Thumbnail | `thumbnail.py` | Pollinations.ai image + Pillow text overlay |
| Publish | `pubblica.py` | YouTube Data API v3 upload + `calcola_publish_slots` for scheduling |

### Clip source (`VIDEO_SOURCE` in `.env`)
| Value | Behaviour |
|---|---|
| `pexels` | Stock only (default) |
| `ibrido` | First `VIDEO_AI_MAX_CLIPS` clips generated by AI, Pexels fills the rest |
| `ai` | Every clip generated, Pexels never called |

`moduli/video_ai.py` holds the providers (`replicate` / `fal` / `luma` / `openrouter`,
chosen with `VIDEO_AI_PROVIDER`, key in `REPLICATE_API_TOKEN` / `FAL_KEY` /
`LUMA_API_KEY` / `OPENROUTER_API_KEY`, model overridable with `VIDEO_AI_MODEL`).
`openrouter` is the odd one: OpenRouter serves no text-to-video model, so it asks an
image-output model (default `google/gemini-2.5-flash-image`) for the scene and builds
the clip locally with an ffmpeg Ken Burns move (`_clip_da_immagine`). Providers listed
in `PROVIDER_IMMAGINE` get a still-frame prompt instead of a camera-movement one, and
their generator returns a local path rather than a URL — `genera_clip` accepts both. Add new providers there following the existing
pattern and register them in `PROVIDER_DEFAULTS` + `_GENERATORI` — the wizard and the
TUI build their menus from that dict, so nothing else needs editing.
