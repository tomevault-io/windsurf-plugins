﻿# AGENTS.md

面向 Codex / AI 编码助手 / 笔记整理助手的本库工作规范。

本库是 Obsidian 考研笔记库，包含数学、英语、PDF/PPT 原始资料、OCR 工具、模板和 Obsidian 配置。所有助手开始工作前必须先阅读本文件，并优先遵守更具体目录中的 `AGENTS.md`。

## 1. 基本原则

1. 开始工作前，先阅读当前目录及上级目录中的 `AGENTS.md`。
2. 仓库内规则优先于全局规则；更具体的规则优先于通用规则。
3. 不要覆盖用户已有修改、手写补充、批注、错题记录。
4. 不要删除、重命名、移动重要文件，除非用户明确要求。
5. 不确定、缺上下文、OCR 不清时，标记 `待确认`，不要编造。
6. 当前目录如果不是 Git 仓库，应明确说明无法创建 Git 备份提交，并改用只新增、不覆盖的安全策略。

## 2. 大改前必须确认

以下情况属于大改，执行前必须先询问用户：

1. 修改多个既有文件或大面积重排内容。
2. 重构目录结构。
3. 批量移动、重命名、删除文件。
4. 修改配置文件、插件目录、索引目录、隐藏目录。
5. 覆盖已有笔记、章节、用户补充或错题记录。
6. 运行可能影响大量文件的格式化、转换、清理脚本。

确认时至少说明：

1. 本次计划修改的范围。
2. 是否只允许修改指定文件。
3. 哪些区域需要保留不动。
4. 是否需要先新建分支。
5. 是否需要先做 Git 备份提交。

大改前默认询问：

> 这次会涉及较大范围修改。要不要我先做一个 Git 备份提交？

## 3. Git 安全规则

大改前先检查状态：

```powershell
git status
```

如果当前目录不是 Git 仓库，说明这一点，不要伪造备份提交。

如果有 Git 仓库且用户确认备份，推荐：

```powershell
git add -A
git commit -m "backup: before major changes"
```

完成整理、修复或重构后，可建议创建结果提交：

```powershell
git add -A
git commit -m "notes: update study notes"
```

未经明确确认，不要执行：

```powershell
git reset --hard
git clean -fd
git checkout -- .
git restore .
```

如需回滚，优先使用更安全的方式：

```powershell
git revert <commit>
git restore --source=<commit> -- <file>
```

## 4. Obsidian 笔记库规则

1. 不要默认修改 `.obsidian/`。
2. 不要默认修改 `.smart-env/` 或 AI 索引数据。
3. 不要删除、移动、重命名原始 PDF / PPT / 图片资料。
4. 不要覆盖 `我的补充`、`错题回流`、用户批注。
5. 新资料和旧笔记冲突时，单独列出冲突点。
6. 不确定、OCR 不清、资料缺页时，标记 `待确认`。
7. 图片放到对应章节的 `fig` 或草稿资产目录。
8. Markdown 保持 Obsidian 兼容，内部链接使用 wikilink，例如双中括号包裹的笔记名。
9. 使用 frontmatter 标记笔记类型、来源、状态和标签。

## 5. 数学 PDF 入库工作流

数学资料入库时，不使用 408 模板。当前正式标准是 `工具/模版文件夹/标准数学笔记模板.md`。后续数学章节笔记必须从 `工具/模版文件夹/标准数学笔记模板.md` 出发，先形成章节级“理解母稿 / 章节复习母稿”，再决定是否拆成基础知识、方法、题目、错题等小卡。

核心原则：

1. 先做一次资料识别与边界确认：识别 PDF 属于高数、线代、概率论的哪一章，记录来源路径、页数、页码范围、是否扫描型 PDF；原始 PDF 不移动、不删除。后续步骤复用这次结果，不要反复扫描同一 PDF 元数据。
2. 对整本教材、讲义合集、张宇基础 30 讲这类多章节扫描型 PDF，必须先按目录和页码边界拆章，再对拆出的单章 PDF 逐章 OCR；禁止先对整本 PDF 做正式 OCR。
3. OCR 输出保留在草稿目录，便于复核。若已有本次任务可用且来源正确的逐章 OCR 草稿，优先复用并抽查关键页，不要重复 OCR；整本 OCR 结果只能作为临时参考，不能作为正式笔记入口。
4. 第一产物必须是对齐 `工具/模版文件夹/标准数学笔记模板.md` 的章节级母稿，不是批量小卡。母稿要体现对本章知识的理解、归纳和复习路径，不能停留在模板骨架。
5. 正式知识内容必须逐条打磨：每个概念、公式、方法、易错点都要经过理解和总结，不能把 OCR 原文整段搬进正式笔记。成熟章节母稿必须完成“理解密度 / 知识密度打磨”：在原模板结构内补足章节主线、概念本质、适用条件、判定方式、易混边界、后续用途、做题路径、命题信号、易错反例和最小记忆清单。
6. 每讲默认至少从 OCR `_final/*-assets/` 中精选 1 张高价值图片嵌入母稿；优先使用体系图、流程图、区域图、函数图、公式结构图、关键例题图。若本讲 OCR 资产确实没有高价值图片，必须在 `待确认` 或最终反馈中说明原因和后续人工筛选任务。
7. 小卡只能从母稿中拆出：先在母稿中确认知识体系、命题信号、例题价值和错题回流，再拆 `基础知识`、`方法`、`题目` 或 `错题`。
8. 只为有复习价值、代表性或易错价值的题目生成 `题目` / `错题` 卡片；不得为了“完整”机械拆分低价值小卡，也不得编造题目。
9. 最后合并做一次质量门检查：frontmatter、Obsidian 链接、图片引用、公式渲染、Dataview 查询、命题信号表、例题索引、错题回流、`待确认` 任务、用户补充/错题回流保护。母稿质量门还必须确认：至少 1 个 `图像精读` 或明确无图原因；概念理解、做题路径、命题信号、易错点、反例边界、最小记忆清单非空且可复习；没有整段搬运 OCR 原文；例题仍只进入索引，未经 PDF 复核不写完整题解。不要在每个小步骤重复做同一批检查。

### 5.1 新增数学资料硬性入口

当用户新增数学 PDF、要求“按工作流入库”“转为笔记”“处理新资料”或类似任务时，必须先执行本入口，不得跳步：

1. 开始前先复述本次执行边界，至少说明是否只做拆章、是否 OCR、是否生成笔记、是否新增脚本、哪些目录不动。
2. 第一阶段只能做资料识别与拆章边界确认：读取 PDF 总页数、目录页、章节标题、印刷页码、PDF 页码偏移和扫描型状态。
3. 第二阶段只能做拆章。拆章 PDF 统一输出到 `电子资源/split/<资料名或学科名>/`；禁止输出到学科笔记目录，例如 `张宇-线性代数/split/`。
4. 拆章完成后必须停止并反馈拆章数量、页数覆盖、首页/末页边界验证方式和待确认项；除非用户已经在同一轮明确要求继续 OCR，否则不得自动进入 OCR。
5. OCR 只能以 `电子资源/split/<资料名或学科名>/<单章>.pdf` 为输入逐章执行；禁止把 `电子资源/source/` 下的整本 PDF 作为正式 OCR 输入。
6. 生成章节母稿只能在拆章边界和逐章 OCR 已确认后执行；可以先建章节级结构和复核任务作为暂存骨架，但不能把骨架视为完成。最终母稿必须继续做知识密度打磨；不得用脚本批量生成未经逐条理解的正式知识正文。
7. 如果用户说“只 split”“只拆章”“先别 OCR”，必须严格停在拆章阶段。
8. 如果用户没有明确允许 OCR 或生成笔记，默认只做到拆章和边界清单。
9. 如果既有规则、旧流程、旧目录和本入口冲突，以本入口为准。

`工具/模版文件夹/标准数学笔记模板.md` 标准结构：

1. `来源说明`：列出 PDF、OCR 草稿、对照草稿和本文件定位。
2. `复核边界`：说明哪些题干、选项、图像、公式必须回 PDF 核对。
3. `考点权重总览`：按 `基础`、`高频`、`易混`、`后续依赖` 标注复习动作。
4. `知识体系`：只放本章主干层级、关键对象和后续可链接入口。
5. `概念区`：定义、公式、定理、条件、变量解释和适用范围。
6. `做题动作区`：看到题目后如何判断、如何下手、如何避免误用。
7. `命题信号 -> 方法入口`：至少包含命题信号、优先想到的方法、关联笔记、易错提醒。
8. `典型例题索引表`：只列编号、考点、方法入口、是否建议拆卡、复核状态；题干、选项、答案和图像必须回 PDF 复核后才能写入正式题卡。
9. `分主题易错点`：按知识模块拆分，例如 `函数易错`、`极限易错`、`连续易错`、`拆卡 / OCR 易错`，不要只堆成一段。
10. `反例 / 边界情况`：记录结论不能套用的条件、反例和易混边界。
11. `Dataview 查询块`：汇总本章基础知识、方法卡、题目 / 错题、AI 草稿待复核。
12. `后续章节链接`：连接到导数、积分、泰勒、洛必达、零点定理、中值定理等后续入口。
13. `错题回流入口`：错题不只堆在错题目录，要回流到对应基础知识、方法卡、易错点或反例边界。
14. `最小记忆清单`：沉淀必须背熟的定义、判定、公式、方法边界和高频易错结论。
15. `待确认`：必须写成可执行复核任务，例如“回 PDF 核对例 1.15 选项和答案”“检查某图是否需要截图嵌入”，不要只写泛泛的“待确认”。

模板标准：

1. `工具/模版文件夹/标准数学笔记模板.md` 是数学章节笔记第一标准；如果其他模板或旧流程和它冲突，以 `工具/模版文件夹/标准数学笔记模板.md` 为准。
2. `工具/模版文件夹` 只作为 Obsidian 手动起稿骨架，用于快速生成 frontmatter、空表格、Dataview 查询块和基础栏目；它不是最终质量标准。
3. 以后更新 `工具/模版文件夹` 中的数学模板时，应向 `工具/模版文件夹/标准数学笔记模板.md` 的结构靠齐，而不是另起一套格式。
4. 不要把模板填满当作完成笔记。完成标准是内容经过理解、归纳、复核，并且能支持复习和做题。

建议笔记类型：

- `章节理解母稿` / `章节复习母稿`：优先级最高的章节产物，结构对齐 `工具/模版文件夹/标准数学笔记模板.md`，用于沉淀本章完整理解、复习入口和拆卡依据。
- `基础知识`：从母稿中拆出的定义、定理、公式、性质、例题、易错点。
- `方法`：从母稿中拆出的通用解题套路、识别信号、适用条件、反例。
- `思维导图`：章节入口页，通常命名为 `x-0 xxx思维导图.md`，可承接母稿中的知识体系和复习入口。
- `题目` / `错题`：题干、解法、关键一步、复盘、举一反三；未回 PDF 复核的题，不写成正式题解。
- `同类题目汇总`：用 Dataview 按标签、类型、评分动态汇总；同类题数量不足或价值不高时不强行新建。
- `补充知识`：主线之外但有价值的证明、图解或扩展。

## 6. 脚本与生成器使用规范

本库笔记工作的核心是逐条理解、整理、归纳和总结。脚本与生成器只能辅助外围工作，不能代替知识加工。

禁止用脚本或生成器批量完成以下内容：

1. 批量生成正式知识正文、概念解释、公式说明或定理总结。
2. 批量生成方法总结、命题信号、易错点、反例边界或最小记忆清单。
3. 批量生成题解、答案、例题索引结论或错题复盘。
4. 批量把 OCR 文本切块后直接写成正式笔记。
5. 批量制造看似完整但未经逐条理解和复核的 Markdown 文件。

允许脚本或生成器做以下辅助工作：

1. OCR、PDF 页数读取、目录读取、页码范围识别、文件清单统计。
2. 生成空白骨架、frontmatter 占位、空表格、Dataview 查询块。
3. 检查 frontmatter 字段、Obsidian 链接、图片引用、Dataview 字段、Markdown 标题层级。
4. 汇总 `待确认`、列出可能断链、统计未复核题目或 AI 草稿。
5. 对批量候选内容做清单，不直接变成正式知识结论。

执行边界：

1. 生成器只能建空壳和检查，不能代替理解、归纳、总结。
2. 任何影响多个文件的脚本、格式化、转换、清理或生成任务，都属于大改，执行前必须说明范围并询问是否先做 Git 备份提交。
