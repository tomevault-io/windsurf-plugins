# CLAUDE.md

Project guide for Claude Code working in **GE-Sim-V2-tour** — a closed-loop VLA
(video world-model + policy) simulation benchmark built on AgiBot's GE-Sim 2.0.
Read this before touching anything.

## What this repo is

A thin orchestration layer (in `scripts/` + `run_stage1.sh`) that drives a
**closed-loop simulation**: a video world model generates frames, a VLA policy
produces actions from those frames, and a remote VLM "World Judge" scores the
result against a task instruction. The heavy ML code lives in the **`gesim`
git submodule** (AgiBot's `GE-Sim-V2`), pinned to an upstream commit. We do
*not* modify submodule code except via a tracked patch (see "gesim submodule").

```
run_stage1.sh        one-shot entry: setup -> services -> preflight -> closed loop -> verify
scripts/             orchestration (Python + bash). ALL our code is here.
  env.sh             sourced in every shell; exports paths, CUDA, conda, MiMo config
  setup_gesim_submodule.sh   init submodule + apply our local patch (idempotent)
  launch_services.py start/probe world-model (HTTP :9000) + policy (WS :8000)
  run_stage1_eval.py 3-demo closed-loop rollout with in-loop MiMo judging
  vlm_reward_client.py MiMoRewardClient — our RewardClient impl (the World Judge)
  download_checkpoints_v2.py chunked Range downloader (resumable, anti-truncation)
  test_mimo_api.py   MiMo preflight (exit 0/1/2 semantics)
  verify_outputs.py  deliverable checks (exit 1 = fail)
  secrets.env         GITIGNORED — real API keys (HF_TOKEN, MIMO_API_KEY, GITHUB_TOKEN)
gesim/               third-party submodule (GE-Sim 2.0). Tracked only as a pointer.
patches/             our local modifications to gesim (Stage 1) + R2E2R (Stage 2), applied by setup scripts
outputs_stage1/      GITIGNORED — eval artifacts (videos, logs, reports), regenerated by re-running
run_stage2.sh        (Stage 2) one-shot entry: setup -> preflight -> Phase1 -> Phase2 -> verify
outputs_stage2/      GITIGNORED — R2E2R generated episodes, regenerated by re-running. See "Stage 2" below.
```

## Environment & hard constraints (READ FIRST)

These are user-mandated constraints. Violating them breaks the box.

- **GPU/driver is fixed at 580.159.03 (NVIDIA A800-SXM4-40GB, headless server).**
  NEVER change or reinstall the driver. The `gesim` env ships `torch 2.7.0+cu126`
  (CUDA 12.6 runtime bundled in the wheel) — it does **not** touch the system CUDA
  or driver. Do not install a different CUDA that could clobber the local 11.8.
- **Disk: `/` is small (~55G free). ALL installs/downloads go under `/mnt/robot/`.**
  `env.sh` already pins `HF_HOME`, `HF_HUB_CACHE`, `PIP_CACHE_DIR` to
  `/mnt/robot/.cache/...`. Conda envs live under `/mnt/robot/conda/envs/`.
  Never `pip install` into the base env or write large files to `/`.
- **NEVER develop in the `cc` conda env** (`/home/vipuser/.conda/envs/cc`). It is
  the default-active env in this shell — explicitly `conda activate gesim` (or the
  target env) before running anything. Create new envs under `/mnt/robot/conda/`.
- **Secrets are never hardcoded.** `MIMO_API_KEY`, `HF_TOKEN`, `GITHUB_TOKEN` live
  only in `scripts/secrets.env` (gitignored) and are loaded into the environment by
  `env.sh`. Access credentials are documented in
  `/mnt/genesis-world-tour-docs/user_access_methods.txt` (outside the repo) — do
  not print or commit them. `vlm_reward_client.py` reads keys from `os.environ`
  only; it never logs them.
- **Stay in `/mnt/GE-Sim-V2-tour/`** as the dev root.

### Conda envs (created at `/mnt/robot/conda/envs/`)

| env       | purpose                                  | used by                |
|-----------|------------------------------------------|------------------------|
| `gesim`   | world-model server, eval driver, torch   | launch_services (WM), run_stage1_eval |
| `openpi`  | π0.5 policy server (Physical-Intelligence)| launch_services (policy) |
| `autosim`, `lerobot-arena*` | other sims / arena   | (not part of Stage 1)  |

`launch_services.py` launches cross-env subprocesses via
`conda run -n <env> --no-capture-output` (falls back to `source activate`) and
sets `CUDA_VISIBLE_DEVICES=0` + `PYTHONPATH=gesim/openpi_serving` for each.

## The closed-loop architecture

```
EpisodeBundle.load(demo) ──► WorldModelEnv(reward=MiMoRewardClient)
        reset(bundle, conditioning="action")
            │
            ▼  (per step, ×8 per demo)
   OpenPIPolicy.infer(obs)  ──► actions (horizon,16)   [WS :8000, π0.5]
            │   compress_actions=True  ──► 25 actions/chunk (not per-frame)
            ▼
   env.step(actions)
      ├─► WorldModelEnv posts actions to HTTP :9000  ──► 25 frames  [GE-Sim 2B, 4 denoise steps]
      ├─► last frame = next obs
      └─► MiMoRewardClient.evaluate(head_frames, task) ──► RewardResult  [remote VLM, in-loop]
            │
   save_video(rollout_multiview.mp4, fps=16)
   MiMoRewardClient.evaluate_with_reasoning(...)  ──► reasoning + final score (post-rollout)
```

**Two services (started by `launch_services.py`, detached, PIDs in `outputs_stage1/logs/*.pid`):**
- **World-model server** — `gesim` env, `python -m gesim.server --model gesim_v2 --config
  configs/gesim_v2.yaml`, HTTP `:9000`, health at `GET /healthz`.
