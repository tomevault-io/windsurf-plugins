# 多项目 AI 代码质量唯一权威契约

## 1. 权威范围

本文件是本仓库多项目 AI 代码质量流程的唯一权威契约。命令只校验参数并编排流程，脚本只处理仓库同步、受保护身份配置和邮件投递，Skill 只处理 HTML 呈现。`project-registry.yaml` 只提供项目成员与配置，不能覆盖本文件的任何语义。其他文件不得扩大或改写本文件的审查、报告、投递和失败语义。发生冲突时，停止受影响流程并用中文报告冲突。

活跃命令只包含实际运行所需的参数校验、受信入口调用、结果校验和流程编排，不得包含 `DoneClaim` 等计划完成声明、证据写入、QA 场景、人工验收清单或其他开发期脚手架。

所有用户可见的标题、说明、发现、警告、失败和结果必须使用中文。路径、Git 引用、配置键和代码标识可保留原文。

本流程只做当次代码质量审查，不追踪跨日问题状态，不审查业务知识，不生成 JSON 报告、独立邮件主题文件或投递与同步事件日志，也不提供提醒、告警或调度服务。不得删除、迁移或改写既有 `reports/**` 数据。

## 2. 项目注册表与同步边界

`project-registry.yaml` 是唯一的项目成员与配置来源。它必须纳入版本控制、不得包含秘密，并且只能包含声明式项目数据，不能包含凭据、工作流指令或代理指令。不得用目录扫描、Git remote、旧状态、同步输出、工作区内容或固定项目集合补充或替代注册表。

注册表顶层只允许逻辑结构 `version: 1` 和 `projects` 列表。每个项目必须包含非空字符串 `project_id`、`name`、`code_dir`、`standards_dir`、`default_branch`、`repository_url_config_key`，可选 `enabled` 必须为 Boolean，省略时为 `true`。`project_id` 长度为 1 至 64，只接受小写 ASCII 字母、数字和内部连字符，且首尾必须为字母或数字，即匹配 `^[a-z0-9](?:[a-z0-9-]{0,62}[a-z0-9])?$`。`repository_url_config_key` 长度为 1 至 128，只接受大写 ASCII 字母、数字和下划线，必须以大写字母开头，即匹配 `^[A-Z][A-Z0-9_]{0,127}$`；在读取配置值前，受信同步脚本还必须确认该键属于专用仓库 URL 配置命名空间，不属于时将注册项标记无效，且不得尝试读取其值。`default_branch` 必须通过第 10 节既有的窄字符 ref 校验。

`code_dir` 规范化、解析规范路径并检查符号链接和重解析点后，必须位于仓库内 `data/code/` 之下；`standards_dir` 经同样检查后，必须位于 `standards/projects/` 之下。路径不得指向各自根目录本身，不得越界、替换或经过不安全链接。首次同步前 `code_dir` 可以不存在，但必须先对词法规范化目标及全部现存祖先目录完成边界、符号链接和重解析点校验，只允许受信同步脚本安全创建目标，并在创建后重新校验规范路径。注册项目之间的代码目录不得重叠或碰撞，规范目录也不得重叠或碰撞，`repository_url_config_key` 不得重复；大小写或规范路径等价也视为碰撞。

注册表缺失、不可读、无法安全解析、顶层结构无效、`version` 不是整数 `1`、`projects` 不是列表或存在重复 `project_id` 时，必须关闭失败并停止所有依赖项目的处理。单个条目的字段缺失、未知字段、类型或格式无效、路径不安全或配置键无效时，只将该条目标记无效；路径或配置键发生碰撞时，将碰撞组内全部条目标记无效。所有条目级错误都必须报告，其他无关有效条目继续。

省略项目选择时，选择当前注册表中全部有效且 `enabled: true` 的条目。显式选择时，只选择与有效且已启用条目匹配的 `project_id`；未知、已禁用或无效的选择必须跳过并报告。省略选择时，`enabled: false` 本身不是失败，也不必作为跳过失败报告。

仓库同步只能由受信同步脚本完成。`daily-review` 必须在同一次流程中把当前已校验注册表快照及从该快照确定的本次所选条目交给该脚本；脚本只能处理这些所选条目，流程也只消费这次调用直接返回的项目、状态、本地路径、默认分支、固定提交 SHA 和中文说明。结果必须逐项匹配所选条目中的 `project_id`、`code_dir`、`default_branch` 及其 `repository_url_config_key` 绑定关系；未选择、已禁用、重复或额外项目的结果必须拒绝。只有受信同步脚本可以在确认配置键属于专用仓库 URL 配置命名空间后读取对应的受保护仓库 URL，并在 `data/code/` 内执行同步操作；模型、审查代理和 `daily-review` 不得解析、读取或输出 URL 或配置值。同步直接结果必须保持既有且仅有的七个字段，不得增加认证字段或以任何形式返回配置值。不得依赖先前执行的同步命令、缓存、日志、旧输出或旧工作区。直接结果缺失、结构无效、路径或绑定不一致、SHA 无法确认的项目必须跳过，不得阻断其他可靠项目。

仅受信同步脚本可以从已通过专用仓库 URL 配置命名空间校验的 `<prefix>_URL` 键名派生并读取受保护同级键 `<prefix>_USERNAME` 和 `<prefix>_PASSWORD`；同级键不是注册表字段，注册表结构不得因此改变。两者都不存在时使用匿名访问。两者恰有一个存在、任一同级键重复、任一值为空、任一值超过 1024 个 Unicode 码点、任一值包含 Unicode `Cc` 类控制字符，或凭据对应的仓库 URL 不是 HTTP 或 HTTPS 时，受信同步脚本必须在任何网络 Git 操作前以固定、脱敏的中文说明只将该项目标记失败，其他独立项目继续。通过 HTTP 使用凭据表示操作者显式接受凭据及仓库传输不受 TLS 保护、可能被明文窃听或篡改的风险；应优先迁移至 HTTPS。

合法凭据只能通过一次性临时 `GIT_ASKPASS` 提供给该项目的 clone、fetch 或 pull，且每次调用必须设置 `GIT_TERMINAL_PROMPT=0` 和空的 `credential.helper`。临时 askpass 程序及其路径不得包含秘密，只能从该次受控进程环境取得凭据，并且仅在 Git 提示所对应的已校验 HTTP 或 HTTPS URL 的 origin 与该项目绑定 origin 完全一致时应答；origin 必须按协议、规范化主机名和有效端口绑定，HTTP 省略端口时按 `80`、HTTPS 省略端口时按 `443`，HTTP 与 HTTPS 即使主机名和数值端口相同也属于不同 origin。任何 origin 不一致都必须在认证前脱敏失败；携带凭据的 HTTP clone、fetch 或 pull 每次都必须设置 `http.followRedirects=false`。脚本必须在成功、失败、取消和异常等所有退出路径删除临时 askpass、清除进程内凭据并恢复临时环境。凭据不得进入 URL、命令行参数、对象表示、文件、标准错误、异常、同步输出、报告或持久 Git 配置，所有认证失败只能使用不含秘密和配置值的固定中文说明。

手动 `code-review` 不得调用同步脚本或同步命令，不得解析配置键或要求、读取、推断任何仓库 URL 和同步结果。它只使用当前已校验注册表中所选项目的 `code_dir` 受控本地工作区。每个所选项目开始审查时，必须先用本节允许的隔离 `git log` 读取并校验实际提交 SHA，将完整小写 40 位 SHA 固定为本次手动审查来源；无法固定 SHA 时只跳过该项目。不得读取未提交内容，不得把本地工作区描述为已同步或远端最新。

除受信同步脚本外，审查流程不得执行 clone、fetch、pull 或切换分支。提交元数据和变更只能通过 OpenCode `bash` 权限中固定允许的强隔离命令形态读取。固定前缀必须逐字为 `git --no-pager -c core.hooksPath=NUL -c core.fsmonitor=false -c core.pager=cat -c color.ui=false -c diff.external= -c interactive.diffFilter= -c protocol.ext.allow=never`，其后只允许以下子命令与固定安全选项：

1. `log --no-show-signature --no-ext-diff --no-textconv --no-color`
2. `diff --no-ext-diff --no-textconv --no-color`
3. `show --no-show-signature --no-ext-diff --no-textconv --no-color`

`log` 和 `show` 必须禁用签名显示；`diff` 没有签名显示语义，不得添加签名选项。三种形态都必须保持禁用 pager、颜色、Hook、ext-diff、textconv、fsmonitor、diff filter、外部协议、别名替换和其他外部执行能力。固定部分不得改变；动态部分只允许已校验的日期、完整提交 SHA 或窄字符 ref，不得包含路径、配置项、额外选项、环境赋值、Shell 或 PowerShell 元字符。任何不能最终匹配上述 OpenCode 固定允许形态的调用都不得执行，也不得用管道、重定向、命令连接或包装命令替代。

## 3. 审查窗口与范围

系统时区固定为 `Asia/Hong_Kong`。日报默认选择前一自然日，窗口为本地前一日 `00:00:00`（含）至当日 `00:00:00`（不含）。提交时间必须转换到同一时区后判断。

显式 `date` 表示该日期的完整本地自然日。`date-range` 从开始日期 `00:00:00`（含）到结束日期次日 `00:00:00`（不含），不能与 `date` 同时使用，开始日期不得晚于结束日期。

手动审查必须明确给出日期、日期范围或提交，不得默认审查全部历史。可用范围条件为项目、日期或日期范围、提交、分支、文件和目录。项目选择遵循第 2 节当前注册表语义；同类多值取并集，不同类条件取交集，文件与目录先取并集。项目、分支、提交和路径都必须校验，显式提交不能绕过其他条件。范围为空时输出中文“范围内无提交”，不得伪造发现或成功数量。

文件与目录过滤不得作为 Git 参数传递，也不要求 Git 参数分隔符。流程先按已校验的日期、SHA 或 ref 读取允许的提交元数据与差异，再使用相对于该项目已注册 `code_dir` 的规范化路径在内存中完成文件与目录过滤；越界路径必须在读取前拒绝。

报告日期按以下顺序确定：存在 `date` 或 `date-range` 时取窗口起始日期；只有 `commit` 而没有日期条件时，取全部所选提交中最早的 Git Author Date，转换为 `Asia/Hong_Kong` 后的本地日期。日期无法读取或范围内没有提交时不得生成个人报告。

每次审查只以本次固定提交、可见 diff 和理解变更所需的最少上下文为依据。旧报告、旧工作区和未读取代码不能作为当前事实。

## 4. 受信身份映射与跨项目聚合

提交归属只按 Git Author Email 通过受信身份接口解析。模型不得读取 `.env`、收件人映射、领导邮箱或 SMTP 凭据，也不得根据姓名、邮箱外观、历史目录或提交内容猜测用户。
