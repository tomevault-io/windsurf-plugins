# Spark Pulse — Project Context

## Project Overview

**Spark Pulse** is a Python/React web control plane and CLI tool for [spark-vllm-docker](https://github.com/eugr/spark-vllm-docker). It provides a unified dashboard for managing AI model deployments on NVIDIA DGX Spark hardware — covering recipe browsing, deployment lifecycle, live monitoring (GPU/CPU/RAM/disk), cache cleanup, and configuration. It also exposes an MCP (Model Context Protocol) server for AI assistant integration.

**Tech stack:**
- **Backend:** Python 3.10+, FastAPI, uvicorn, PyYAML, Pydantic, Authlib (OIDC), SSE (Server-Sent Events)
- **Frontend:** React 19, Vite 6, TypeScript, Tailwind CSS 4, lucide-react icons, react-router-dom v7
- **CLI:** Click — manages start/stop, systemd installation, MCP server launch
- **Packaging:** setuptools, semantic-release (npm + PyPI), GitHub Actions CI

**Architecture:**
```
spark_pulse/
├── app.py              # FastAPI factory, SPA serving, MCP endpoint
├── cli.py              # Click-based CLI (start, install, mcp, etc.)
├── config.py           # config.yaml + settings.json + env var merge
├── auth.py             # OIDC middleware, login/callback/logout routes
├── service.py          # systemd unit install/uninstall/status
├── mcp_server.py       # MCP stdio transport for AI assistants
├── mcp_http.py         # Shared MCP RPC handler (tool definitions + dispatch)
├── sse.py              # SSE event broadcasting for log streaming
├── routers/            # FastAPI route modules (cache, config, custom_files, custom_recipes, deployments, git_update, memory, mods, recipes, settings)
├── tools/              # Shared business logic (cache, custom_files, custom_recipes, deployments, git_update, mods, recipes, system)
├── mock/               # Mock providers (cache, deployments, recipes, system) for simulation/testing
├── ui/                 # Built React SPA output (generated by `npm run build`)
└── data/               # Runtime data directory for systemd service
```

The frontend (`web/`) is a separate Vite/React app built independently and copied into `spark_pulse/ui/` as a static bundle. The FastAPI app serves the SPA via a catch-all route and also exposes REST APIs under `/api/*` and `/auth/*`.

## Building, Running & Testing

### Install dependencies
```bash
# Python
pip install -e ".[dev]"

# Frontend
cd web && npm install && cd ..
```

### Build frontend
```bash
./scripts/build-ui.sh
# or manually:
cd web && npx tsc -b && npx vite build && cd ..
```

### Start services
```bash
# Full dev (backend + frontend hot-reload)
./scripts/run-dev-server.sh

# Backend only (simulation mode, port 8100)
./scripts/run-backend.sh

# Production (no hot-reload, built UI)
./scripts/run-production.sh

# With mock OIDC provider for SSO testing
./scripts/run-dev-oidc-full.sh    # full stack
./scripts/run-dev-oidc.sh         # backend only
```

### CLI
```bash
spark-pulse start                 # Run web server
spark-pulse install [--user]      # Install systemd service
spark-pulse uninstall [--user]    # Remove systemd service
spark-pulse status [--user]       # Check service status
spark-pulse start-service         # Start the systemd service
spark-pulse stop-service          # Stop the systemd service
spark-pulse mcp                   # Start MCP server for AI assistants
```

### Tests
```bash
pytest                           # Run all tests
pytest -v                        # Verbose output
pytest tests/test_tools_recipes.py  # Single file
```

Tests live in `tests/` (18 test modules total) and cover:
- **Config & Auth:** `test_config.py`, `test_auth.py`, `test_config_router.py`
- **End-to-end:** `test_e2e_oidc.py`, `test_e2e_custom_recipes.py`, `test_e2e_git_update.py`
- **Routers:** `test_router_custom_files.py`, `test_router_custom_recipes.py`, `test_router_git_update.py`
- **Tools:** `test_tools_cache.py`, `test_tools_custom_files.py`, `test_tools_custom_recipes.py`, `test_tools_deployments.py`, `test_tools_git_update.py`, `test_tools_recipes.py`, `test_tools_system.py`
- **System:** `test_service.py`, `test_mock_system.py`

### CI (GitHub Actions)
- **`unit-tests.yml`** — on PR and main push: installs Node + Python deps, builds frontend, runs pytest
- **`release.yml`** — on push to `main`: uses `semantic-release` (npm) for version bump + changelog, then publishes to PyPI
- **`pre-commit.yml`** — runs pre-commit hooks on PRs
- **`pr-title.yml`** — validates PR title format for semantic-release

## Frontend Structure

The React frontend (`web/src/`) includes:

### Pages
- **RecipesPage** — Browse and manage deployment recipes
- **JobsPage** — View and manage active deployments
- **CachePage** — Monitor and clean HuggingFace cache
- **MCPPage** — MCP server documentation and tooling
- **MemoryPage** — Project memory and context management
- **SettingsPage** — System configuration and preferences
