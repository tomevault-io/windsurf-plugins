# Refrain agent contract

Read `SPEC.md`, `docs/PRODUCT.md`, `docs/ARCHITECTURE.md`, and `docs/ROADMAP.md` before changing programme order or public contracts.

## Authority and boundaries

- Project naming is `Refrain` / an `air` / `hum`; **Refrain hums an air.** is shared across English and Chinese. `packages/renderer/src/ui-copy.ts` owns interface prose; language is local presentation state, never musical identity. Preserve authored text and exact names; do not invent a Chinese product name or a second localized renderer.
- `air@1-experimental` is the canonical music source for the current development line. AIR@0 remains an exact historical reader and explicit migration input, not a second active grammar. Compiled events, MIDI, WAV, visual layouts, and browser state are projections.
- The current host agent chooses musical expression. Compiler code may normalize notation, expand explicit transforms, enforce ranges and safety, and emit warnings; it must not silently rewrite music for taste.
- Keep the core stateless. Do not add user accounts, OAuth, hosted relationship memory, an official work library, or a hidden composition model.
- Refrain remains self-hosted rather than a Refrain-operated backend. The canonical private OpenAI path is one loopback HTTP origin plus an operator-owned outbound Secure MCP Tunnel; do not expose the origin publicly, copy another product's OAuth issuer, or fork one deployment per host.
- Relationship context remains host-side and may inform the authored air and optional caption. `hum` must not accept, echo, hash, or store private conversation context.
- Production Canvas aesthetics come from the Faye/Selen-approved visual-research line. The active private G candidate is the selective Selen v21 transplant in `packages/renderer`; preserve that source authority and do not redraw the composers from screenshots or restore the retired generic density-lane UI. The soundbench remains disposable functional engineering UI.
- Tier 1 URL and Tier 2 MCP Canvas must import the exact same renderer package and preserve one visual-language contract. A host adapter may wrap it but must not fork product UI.
- Audio never auto-plays in chat/browser surfaces. A user gesture starts playback. Device-authorized autonomous playback is a later, separate integration boundary.
- Sound assets require asset-level provenance. A package license does not determine the license of bundled samples.
- Project-original functional materials use SUL-1.0; authored content and example music use CC BY-NC-SA 4.0. `LICENSING.md` owns the path-level scope; preserve all third-party terms and never call this OSI open source. Changing the selected licenses or their scope requires owner confirmation.

## Canonical paths

- `packages/identity`: the one synchronous browser-safe, cross-runtime SHA-256 primitive for deterministic text identities. Keep domain serializers in their owning packages; do not add a second hash implementation or Node-only crypto to browser-shared code.
- `packages/air-schema`: current AIR@1 source types/parser/diagnostics, exact AIR@0 historical parsing and explicit migration, closed rational/conductor/groove/phrase/technique syntax, and carried vocabulary identity. Version dispatch must remain format-exact; do not coerce an invalid object into another generation.
- `packages/compiler`: versioned expansion, conductor/meter schedule, normalized motif material, phrase/segment projections, explicit technique/tuplet/groove lowering, structural validation, and listening lint. AIR@1 compilation consumes the exact immutable vocabulary carried by its source; installed pack state must never mutate vocabulary implicitly.
- `packages/soundpack`: stable model-facing identity in `instrument-vocabulary.json`; lightweight routing in `sound-catalog.json`; exact implementation/provenance in immutable content-addressed candidate shards under `candidates/sha256`; direct candidate digest pins in `sound-profiles.json`; build-time SFZ and closed versioned synth-family compilers; and strict extension authorities. `vnext.ts` owns the vocabulary-closure / sparse-profile / scene@1 / recipe / palette@1 / binding@1 contracts plus exact ExtensionPack@0 and ExtensionPack@1 `authoring-vocabulary` modules; `pack-manager.ts` owns explicit-root installed/hydrated/shelf/archive-pin state; `proof-packs.ts` assembles the acoustic and synthetic proofs without duplicating candidate authority. `factory.ts` remains shard lookup and exact candidate/profile/palette closure. Do not restore a monolithic implementation manifest, permissive dual reader, legacy profile resolver, or fetch-all default. Historical integrity and current-runtime resolution remain separate for both binding generations. Never move engine defaults back into identity records, conflate validation layers, or create a second gain/ceiling authority.
