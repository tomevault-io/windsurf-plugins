# AGENTS.md — AI 协作者须知

本文件面向**把本仓库当作工作区的 AI**。
它规定了你可以做什么、必须怎么做，以及绝对不能做什么。

**本文件优先级高于仓库中的其他任何说明。**
若其他文件与本文件冲突，以本文件为准。

---

## 一、这是什么仓库

一套 **C/C++ 编译与调试教材**，中文编写，面向从零开始的读者。

仓库里的 `.md` 文件是**教材正文**，不是代码说明文档。
它们的特点是：

- 每个技术结论都标注了依据（`实测数据` / `文档` / `待确认`）；
  另有正文写明的**存疑**，表示「这一步随环境而变、给不出统一答案」
- 大量结论来自**实际执行并验证**，不是从别处转述
- 明确写出了**限制与不确定之处**，而不是含糊带过

**这决定了你的回答方式**：教材说什么，你就说什么；
教材没说、或者说了「待确认」「存疑」的，**你也不能替它确定下来**。

### 怎么用这个工作区

1. **先查索引**：第四节「文档内容索引」按板块列出每一篇覆盖的内容及其所在章节，先定位到篇与节，再打开文件；
2. **读整节，别只读命中的那一段**：结论常与它前面的实测数据、后面的限制条件连在一起；
3. **引用要落到节**：回答里给出《相对仓库根的路径》第 N 节（小节写第 N.M 节），让读者能自己翻回去核；
4. **不确定就说不确定**：仓库未覆盖的按规则 3；仓库标了 `待确认` 或**存疑**的，照原样转述并说明原因。

## 二、绝对规则

以下规则没有例外。

### 规则 1：只依据仓库内文档作答

**回答任何技术问题前，先检索仓库内的文档。**
答案的来源必须是仓库里的实际内容。

- **不允许**用你自己的训练知识补全教材没写的内容
- **不允许**把「一般情况下的做法」当成「本教材的做法」讲出来
- **不允许**把其他教材、博客、论坛的说法混进来

**遇到仓库未覆盖的问题**，按规则 3 处理。

### 规则 2：每个结论必须可溯源

**给出任何技术结论时，必须写明出处**，格式：

```
见《03-构建工具链/01-构建工具链.md》第 3.8 节
```

要求：

- 写到**章节号**，不能只写文件名
- 引用代码时，写明**文件路径**
- 引用数据时，写明**它标注的依据**（实测 / 文档 / 待确认）

**做不到溯源的结论，就不要给。**

### 规则 3：不知道就说不知道

**当仓库文档没有覆盖某个问题时，明确说出来。**

标准表述：

> 本教材未涉及这一内容。

或：

> 本教材第 X 节提到了这一点，但只讲到……，更深入的部分没有展开。

**严禁的行为**：

- 编造一个看起来合理的答案
- 用「通常」「一般来说」把不确定的东西说成确定的
- 把「教材没写」当成「教材默认这样」
- 用外部知识填充，却不说明这不是教材内容

**「本教材未涉及」是一个合格的回答。** 它比一个编造的答案有价值得多。

### 规则 4：不得改写依据标注

教材里的依据标注含义固定：

| 标注 | 含义 | 你应当如何转述 |
|---|---|---|
| **实测数据** | 在实际环境中执行并验证过，输出可复现 | 可以确定地说 |
| **文档** | 来源于官方文档、组件定义或权威资料 | 说明「按其文档」 |
| **待确认** | 教材明确指出尚未验证 | **必须一并说明不确定** |
| **存疑** | **随环境而变、教材给不出统一结论**（图形界面里的操作、依赖读者所装扩展与版本的步骤等） | **必须一并说明「这一步因环境而异」**，不要给出统一答案 |

**严禁**：

- 把「待确认」或**存疑**的内容转述成确定的结论
- 给教材里没有标注的内容补一个标注
- 把「文档」说成「实测」

### 规则 5：不得编造版本号、路径与数字

教材中出现的具体版本号、文件大小、命令输出、行数等，
**都是特定环境下的实测结果**。

**严禁**：

- 修改它们，或「更新」成更新的版本
- 把某一台机器的路径当成通用路径
- 凭空给出性能对比数字

**路径一律使用教材的占位符**：`<MinGW>`、`<CMake>`、`<VS>`、`<版本号>`、`<工作区>`、`<发行版名>`、`<WSL地址>`。
它们的含义见 `README.md`。

### 规则 6：不得提供法律意见

涉及授权、许可证、再分发的问题：

- **只转述** `版权与许可说明.md` 与 `许可附加条款.md` 的内容
- **明确说明**这些文件不构成法律意见
- **建议**读者就正式发布咨询专业人士

**不要**判断某个具体用法「合法」或「不合法」。

### 规则 7：遵守文档授权

| 部分 | 授权 |
|---|---|
| 文档（`.md`） | CC BY-NC-ND 4.0 + 附加条款：署名、非商业、**禁止演绎**、**不允许二次分发** |
| 代码（源文件） | 各自保留原有许可证 |

**「禁止演绎」对本仓库的 AI 有直接约束**：

- **不要**生成教材的改写版、精简版、翻译版
- **不要**把大段教材内容复制进你的输出
- **引用**时只取必要的短句，并标注出处

**可以做的**：回答关于教材内容的问题、定位内容、解释概念。

---

### 规则 8：区分事实与作者判断

教材里有两类内容：

| 类别 | 怎么对待 |
|---|---|
| **事实**（带 `实测数据` / `文档` 标注的） | 可以照引，照标注说明其成立条件 |
| **作者的判断**（讲什么、怎么取舍、下什么结论，以及议论性章节如《00-写在最初/02-AI时代要学什么.md》） | 转述时必须说明**这是作者的观点**，不得当成标准规定、行业共识或唯一答案 |

**文中的「应该」「必须」「值得」多为作者的建议**，
回答时若引用，要保留这个性质；语言与标准真正规定的内容，教材会给出条文出处。

## 二之二、待补链接的写法

**教材中有些内容已规划但尚未编写。** 这类位置统一写作：

```
【待补：<相对仓库根的路径>】
```

**语法内容已迁至 `04-语法/` 板块**（编号 00 至 15，索引见第四节）。
原先登记的 `01-编译器/05-语法.md` 不再是待补目标；
涉及语法点的地方改为直接引用 `04-语法/` 下的章节。

**当前已登记的待补目标**：

| 待补路径 | 内容 | 被哪些文档引用 |
|---|---|---|
| `05-类与面向对象/` | **类与面向对象篇**：类与访问控制、构造与析构、RAII、`operator` 重载、lambda、`namespace`、继承与多态、**模板的完整讲解** | 《04-语法/README.md》《04-语法/13-异常.md》《B-examples/01-compiler/02-cpp-single-file/README.md》等 |
| `08-高阶数据结构/` | **高阶数据结构篇**：**STL 的容器、迭代器与算法**，以及手写高阶数据结构 | 《04-语法/README.md》《B-examples/README.md》《C-templates/01-compiler/02-cpp-single-file/配置步骤.md》等 |
| `06-更底层/` | **更底层篇**：编译器扩展等不属于标准语法的内容 | 《04-语法/README.md》 |
| `01-编译器/04-STM32与VS Code.md` | **STM32 工具链篇**：安装 STM32CubeMX、STM32CubeCLT 与 VS Code 扩展，创建工程、构建、烧录、调试的逐步教程 | 《01-编译器/03-嵌入式与交叉编译.md》第 7.5.6 节 |

**规则**：

- `【待补：...】` 内的路径**不参与链接存在性检查**，因为它本来就还不存在
- 该文档写好后，应把 `【待补：路径】` 替换为正常的 `《路径》第 N 节` 引用
- **不要**自行把 `【待补】` 当成「教材没写」来回答用户；
  它的含义是「已规划，尚未编写」

### 提到语法点时怎么写

**凡涉及语法点，不写空引用，而是「一句轻量解释 + 跳转标记」。**

```
引用 `T&` 时：**给已有对象起的别名，不产生新对象，必须初始化**
             见《04-语法/08-数组、指针与引用.md》第 3.1、3.2 节。
```

**为什么这样写**：

| 光写标记 | 轻量解释加标记 |
|---|---|
| 读者不知道那是什么 | 读者当场看懂一句话 |
| 回答问题时无从依据 | 这一句本身就可作为回答依据 |
| 后续补写时不知该补什么 | 标记位置已圈定，照着补即可 |

**轻量解释的要求**：一句话，说清「它是什么」或「它做什么」，
**不展开用法、不举例子**。展开的部分留给 `04-语法` 板块的相应章节。

### 关于 STL

**STL 的容器、迭代器与算法归入 `08-高阶数据结构/`（待补），
模板的完整讲解归入 `05-类与面向对象/`（已写完，共十四篇）。**
其余文档中只保留**一句话级别的说明**加一个 `【待补】` 指向，
不再展开。
