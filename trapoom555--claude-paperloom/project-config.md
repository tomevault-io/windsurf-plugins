# PaperLoom Vault — Schema

This file is the **authoritative schema** for the vault. All plugin commands and subagents read it here; when you change conventions, change them in this file and the rest follows.

The vault is an LLM-maintained wiki in the spirit of Karpathy's "LLM Wiki" gist. Three layers:

- **Raw sources** (`.sources/`) — immutable PDFs / HTML dumps keyed by `sha256(url)`.
- **Wiki** — `papers/`, `findings/`, `authors/`, `fields/`, `index.md`, `log.md`. LLM-maintained.
- **Schema** — this file.

## Directory layout

```
papers/            one .md per paper (slug = YYYY-MM-title-kebab)
findings/          one .md per atomic finding (slug = finding-<kebab>)
authors/           one .md per author ("Surname, Given")
fields/            one .md per research field (kebab-case)
views/             Dataview filter pages (generated by /paperloom:filter)
.sources/          raw inputs, keyed by sha256(url)
index.md           Dataview-powered catalog
log.md             append-only action log
```

## File-naming rules

- **Paper slug**: `YYYY-MM-<short-title-kebab>` (e.g. `2017-06-attention-is-all-you-need`). Use the publication date.
- **Finding slug**: `finding-<kebab-summary>` (e.g. `finding-self-attention-is-O-n2`). Keep it readable; it appears in wikilinks.
- **Author filename**: `Surname, Given.md` (comma + space; matches citation order). One file per distinct author.
- **Field filename**: kebab-case (e.g. `attention-mechanism.md`).
- Filenames are stable. Do not rename without updating all wikilinks.

## Frontmatter — paper

```yaml
---
type: paper
title: "Attention Is All You Need"
slug: 2017-06-attention-is-all-you-need
authors: ["[[Vaswani, Ashish]]", "[[Shazeer, Noam]]"]
fields: ["[[nlp]]", "[[attention-mechanism]]"]
publication-date: 2017-06-12   # YYYY-MM-DD, required
ingested-date: 2026-04-23      # YYYY-MM-DD, required (set at ingest time)
source-url: https://arxiv.org/abs/1706.03762
arxiv-id: 1706.03762           # null if not arxiv
doi: null
venue: "NeurIPS 2017"          # null if preprint only
quality:
  credibility: 5               # integer 1-5, overall trust in findings vs evidence
  experimental-rigor: 5        # integer 1-5, methodology soundness
  reproducibility: code-released  # code-released | partial | none
  overall: 5.0                 # float 1.0-5.0, computed — see formula below
  rationale: "One-sentence justification."
findings:
  - "[[finding-...]]"
relations:
  cites:        []   # vault papers cited in this paper's bibliography (from scripts/citation_match.py)
  builds-on:    []   # aggregated from this paper's findings' `uses` edges
  supports:     []   # aggregated from this paper's findings' `supports` edges
  contradicts:  []   # aggregated from this paper's findings' `contradicts` edges
  extends:      []   # aggregated from this paper's findings' `extends` edges
  similar-to:   []   # aggregated from this paper's findings' `similar-to` edges
---
```

Required keys: `type`, `title`, `slug`, `authors`, `fields`, `publication-date`, `ingested-date`, `source-url`, `quality.credibility`, `quality.experimental-rigor`, `quality.reproducibility`, `quality.overall`, `quality.rationale`, `findings`, `relations.cites`, `relations.builds-on`, `relations.supports`, `relations.contradicts`, `relations.extends`, `relations.similar-to`.

### Paper-level relations

- `cites` — **bibliographic**. Populated by `scripts/citation_match.py` at ingest (deterministic — no LLM). Entries are only vault papers — the script matches bib entries against existing slugs by arXiv ID / DOI / fuzzy title / author+year. Directional: A citing B does not imply B cites A. No mirror write.
- `builds-on`, `supports`, `contradicts`, `extends`, `similar-to` — **derived from the finding graph**. Main agent aggregates at ingest right after `finding-linker` returns: for each finding-level edge from one of this paper's findings, look up the target finding's `source-paper` and add it to the corresponding paper-level relation (deduped, excluding self-references).
  - Symmetry mirrors the finding-level rule: `contradicts` and `similar-to` are bidirectional (mirror onto the target paper); `builds-on` / `supports` / `extends` are directional.

**`quality.overall` computation** (weighted; computed by `metadata-extractor` at ingest time):

```
repro_score  = {code-released: 5, partial: 3, none: 1}[reproducibility]
overall      = round(0.5 * credibility + 0.3 * experimental-rigor + 0.2 * repro_score, 1)
```

Rationale for weights: credibility (50%) dominates because it captures finding-vs-evidence fit; experimental-rigor (30%) reflects methodology; reproducibility (20%) matters but a paper can still be very credible without open code. Score range: 1.0 (weakest) to 5.0 (strongest).
