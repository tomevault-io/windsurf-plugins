# AGENTS.md

Quick-start guide for AI agents working on **InfiniDysk** (formerly NzbDAV, "The NzbDAV SuperFork").

## What this project is

InfiniDysk is a **WebDAV server** that mounts NZB documents as a virtual filesystem and streams content directly from Usenet providers — without downloading files to disk first. It exposes a **SABnzbd-compatible API** so Sonarr, Radarr, and similar tools can use it as a drop-in download client.

The shipped product is a **single Docker image** that runs two processes:

| Process | Stack | Default port | Role |
|---------|-------|--------------|------|
| Backend | .NET 10 (`backend/`) | 8080 (5000 in local dev) | WebDAV, Usenet streaming, queue/history, SAB API, SQLite DB |
| Frontend | React Router 7 + Express (`frontend/`) | 3000 | Admin UI, auth, proxies WebDAV/API to backend |

Persistent state lives under `CONFIG_PATH` (default `/config`): SQLite DB, settings, blobs.

## Architecture (mental model)

```
Sonarr/Radarr ──► SAB API (/api?mode=addfile|queue|history|…)
                        │
                        ▼
                 QueueManager ──► UsenetStreamingClient ──► NNTP providers
                        │
                        ▼
                 DatabaseStore (WebDAV) ──► virtual files under /view, /nzbs, /content, …
                        ▲
Browser/Plex/rclone ──► Frontend :3000 ──proxy──► Backend :8080 (WebDAV + /api)
```

**Frontend proxy rule:** `frontend/server/app.ts` forwards WebDAV methods, `/api`, and mount paths to `BACKEND_URL`. Authenticated UI requests get `x-api-key` injected automatically.

**Backend startup:** `Program.cs` registers controllers, WebDAV (`DatabaseStore`), hosted services, and runs EF migrations when invoked with `--db-migration` (done automatically in Docker via `entrypoint.sh`).

## Local development

See [CONTRIBUTING.md](CONTRIBUTING.md) for full steps. Minimum env:

```bash
export CONFIG_PATH=/tmp/nzbdav-config
export FRONTEND_BACKEND_API_KEY=$(head -c 32 /dev/urandom | hexdump -ve '1/1 "%.2x"')
export BACKEND_URL=http://localhost:5000
```

Preferred: `./scripts/run-backend.sh` (Terminal 1) + `cd frontend && npm run dev` (Terminal 2; `predev` runs `scripts/sync-dev-env.sh`). After clone, initialize the rapidyenc submodule once (`git submodule update --init libs/rapidyenc`). Manual alternative:

```bash
# Terminal 1 — backend
cd backend && dotnet publish -c Release -o ./publish
mkdir -p "$CONFIG_PATH" && ./publish/NzbWebDAV --db-migration
./publish/NzbWebDAV

# Terminal 2 — frontend
cd frontend && npm install && npm run dev
```

Open `http://localhost:5173` (dev) or `http://localhost:3000` (production build).
