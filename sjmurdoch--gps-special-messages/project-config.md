# CLAUDE.md

Project guide for Claude Code working in this repo.

This is the reproducibility companion to *Inside GNSS* (May/June 2026)
"The Empty Field That Wasn't: GPS, OTAD, and Two Decades of Encrypted
Broadcasts." It rebuilds every quantitative claim and figure in the
article from the raw GFZ navbit + NAVCEN advisory inputs.

## Orientation

Read in this order when first dropped into the repo:

- [README.md](README.md) — what the project is + quickstart.
- [REPRODUCING.md](REPRODUCING.md) — fast path (download DB, verify) and full path (rebuild from raw).
- [DATA.md](DATA.md) — provenance, citations, Zenodo DOI.
- [CLAIMS.md](CLAIMS.md) — every article footnote ↔ verifier or external citation.
- [article/the-empty-field-that-wasnt.md](article/the-empty-field-that-wasnt.md) — the v2 article itself (tracked source; published via GitHub Pages).
- [CITATION.cff](CITATION.cff) — machine-readable citation.

## Layout (one-way DAG)

```
pipeline/   raw archives  → data/messages.duckdb
analysis/   DB            → derived tables in DB + analysis/reports/*.md
figures/    DB + reports  → figures/output/*.{png,pdf}
verify/     DB            → exit code (0 ⇔ all claims hold)
article/    Markdown source + figures → article/site/ (GitHub Pages page) + the-empty-field-that-wasnt.pdf (print)
src/        the GPSSpecialMessages module (parsers, decoders, DB writer)
test/       unit tests (913 without data/ops_advisories; grows with the OA set)
bin/        fetch_zenodo.sh, full_build.sh
data/       arrow_test/ committed; everything else fetched or rebuilt
```

Each bucket reads from the previous and writes to a well-known output.
Per-bucket entry points: `pipeline/run_all.sh`, `analysis/run_all.sh`,
`figures/build_all.sh`, `verify/run_all.sh`, `article/build.sh` (web page) and
`article/build-pdf.sh` (print PDF). End-to-end: `bin/full_build.sh` chains
everything (its final stage, `08_article`, renders the PDF; it skips gracefully
when pandoc/xelatex are absent); designed to run unattended (see top of script
for nohup invocation).

When a researcher asks where new code goes, follow the DAG: a new
quantitative claim → `verify/`; a new derived metric → `analysis/`; a
new chart → `figures/`; new pure helper functions → `src/` with tests.

## Adding a new claim

1. Write `verify/<claim>.jl` (≤100 lines). Follow the pattern in
   `verify/corpus_totals.jl`: read DB read-only, assert with a `check()`
   helper, exit non-zero on divergence.
2. Append it to the loop in `verify/run_all.sh`.
3. Add a row to the table in `CLAIMS.md` linking the article footnote to
   the new script.
4. Run `verify/run_all.sh data/messages.duckdb`; commit only when every
   verifier passes.

Tolerances: counts/exact totals → equality. Test statistics with random
seeds → tight numeric tolerance with the seed pinned. Plot byte-equality
is **not** verified (Cairo embeds timestamps; visual review only).

## Adding a new analysis

1. New script `analysis/<topic>.jl`. Read DB, write the report under
   `get(ENV, "REPORTS_DIR", joinpath(@__DIR__, "reports"))`, not a hard-coded
   `joinpath(@__DIR__, "reports")` — `bin/full_build.sh` sets `REPORTS_DIR` to a
   work-dir path so a full build stays hermetic and never dirties the tracked
   `analysis/reports/`. `mkpath` it before writing.
2. Prepend the report's first line with the AUTO-GENERATED header
   (`<!-- AUTO-GENERATED by analysis/<topic>.jl on <ISO-UTC, e.g. 2026-06-21T07:14:08Z> — do not edit by hand -->`;
   build the timestamp with `Dates.format(now(UTC), dateformat"yyyy-mm-ddTHH:MM:SS") * "Z"` so headers are UTC, not local)
   so hand-written and machine-written reports stay distinguishable.
3. Hook into `analysis/run_all.sh`. Respect FK ordering: scripts that
   write child rows must run after the parents.
4. For DB writes use `INSERT ... ON CONFLICT DO NOTHING`, never
   `INSERT OR REPLACE`. REPLACE is implemented as DELETE+INSERT in
   DuckDB and breaks foreign keys from sibling correlation tables.
5. New table? Add `create_<topic>_table!(db)` in `src/duckdb_writer.jl`
   and a wipe-prelude entry in `analysis/run_all.sh` Step 0.

## Adding a new figure

1. New file `figures/figN_<name>.jl` (CairoMakie) or `.typ` (Typst).
2. Output paths must be `joinpath(@__DIR__, "output", "...")`. Emit
   PNG, PDF, and SVG.
3. Add to `figures/build_all.sh`.
4. Commit the rendered PNG + PDF + SVG outputs alongside the script.
5. CairoMakie embeds creation timestamps and font-cache ordering in PNG
   `tIME` chunks and PDF `/CreationDate` — repeated runs differ by
   ~25 bytes per output. Visually identical. Do not assert byte-equality.

## Running things

| Task | Command |
|---|---|
| Tests | `julia --project test/runtests.jl` (~30 s, expect 913/913 without `data/ops_advisories/`; with it the count grows with the OA file set — all must pass) |
| Article page | `article/build.sh` (Pandoc → `article/site/index.html`; deployed by `.github/workflows/pages.yml` on push) |
| Article PDF | `article/build-pdf.sh` (Pandoc → xelatex → `article/the-empty-field-that-wasnt.pdf`; bottom-of-page footnotes, gitignored output) |
| Pipeline smoke | `julia --project pipeline/04_build_database.jl data/arrow_test/ data/test.duckdb` (~10 s, 3,712 msgs / 2 unique) |
