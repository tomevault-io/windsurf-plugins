# Working on Catppuccin for Zed

`AGENTS.md` is the canonical guide; `CLAUDE.md` is a relative symlink to it.
Documentation and the macOS Computer Use workflow were checked on 2026-09-07.
Check current documentation and the installed Zed version when behavior differs.

## Project and commands

- [justfile](justfile) is the source of truth for setup, builds, cleanup, and releases. Read it and run `just --list` before choosing commands. [.zed/tasks.json](.zed/tasks.json) provides editor shortcuts; prefer the recipes when instructions disagree.
- [zed.tera](zed.tera) is the Whiskers/Tera source for theme colors. Edit this template and regenerate; do not hand-edit generated JSON.
- [extension.toml](extension.toml) identifies the `catppuccin` extension. This checkout is already installed in the user's Zed as a dev extension. Keep the build directory and installed dev-extension directory aligned, especially when using another checkout or worktree.
- Each generated theme file contains Latte, Frappé, Macchiato, and Mocha. The matrix generates an italics and a no-italics file per accent. Only `themes/catppuccin-mauve.json` and `themes/catppuccin-no-italics-mauve.json` are currently tracked; other accents are ignored by [.gitignore](.gitignore).

Run recipes from the repository root:

| Command | Purpose |
| --- | --- |
| `just` or `just --list` | Show available recipes. |
| `just setup` | Install Whiskers with Homebrew on macOS, if needed. |
| `just build` | Generate all four flavors, both italics variants, with the default mauve accent. |
| `just build blue` | Generate the same variants with a blue accent. |
| `just all` | Generate the complete accent matrix. |
| `just clean` | Remove generated theme JSON, including tracked files; use only when cleanup is needed and regenerate afterward. |
| `just release <tag>` | Generate all themes, sign and push a tag, and publish release assets. Use for an explicitly requested release. |

The `build` argument is currently named `flavor`, but it overrides **accent**.
For example, `just build blue` is valid; `just build mocha` does not select Mocha.
Use `just --dry-run build blue` to inspect the underlying command.

## Commit and PR titles

All PR titles targeting `main` and all commit subjects landing on `main` must follow
[Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/):
`type(scope)!: description`, with the scope and `!` optional.

- Use lowercase types such as `feat`, `fix`, `docs`, `ci`, `build`, `chore`, `refactor`, `perf`, `test`, `style`, or `revert`.
- Use `fix` for theme corrections and `feat` for new capabilities. Reserve `style` for formatting-only changes.
- Examples: `fix(markdown): improve heading contrast`, `feat(syntax): add preprocessor highlighting`, `docs: expand theme debugging guidance`.
- Indicate breaking changes with `!` or a `BREAKING CHANGE:` footer, and explain the impact.
- Before merging, verify both the PR title and the final commit subject. For squash merges, use the validated PR title as the commit subject; if individual commits will land, check every subject. Correct nonconforming titles/messages before merging, including autogenerated merge messages, and preserve any breaking-change footer.
