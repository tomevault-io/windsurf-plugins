# RTL Design Project

## Project Overview

This is an RTL design project for developing hardware modules in Verilog.
The project includes RTL source code, reusable library modules, documentation generated during development, and project files for simulation and synthesis.

## Project Structure

```text
.
├── CLAUDE.md              // project instructions (this file)
├── flow_status.md         // live phase-completion snapshot (written by vflow)
├── ddoc/                  // per-module requirement files, inputs for vdesign
├── doc/                   // generated module and IP documentation
├── lib/                   // reusable RTL library modules
│   ├── module_1.v         // single-file library module
│   ├── module_1.md        // documentation for module_1
│   └── module_2/          // multi-file library module
│       ├── module_2.v     // top-level RTL
│       ├── any.v          // submodule used by module_2
│       └── module_2.md    // documentation for module_2
├── rtl/                   // RTL code developed for this project
│   ├── module_m.v
│   └── module_n.v
├── tb/                    // testbenches
│   ├── <module>/          // unit testbench generated by vfill
│   │   └── <module>_tb.sv //   (per-submodule lint/sim during implementation)
│   └── <ip>/              // IP-level bench project scaffolded by vtestgen
│       ├── Makefile       //   top dispatcher, auto-discovers tb_*.sv
│       ├── script/
│       │   ├── library.mk //   per-testcase xvlog/xelab/xsim recipe
│       │   └── rtl.f      //   generated RTL hierarchy filelist
│       ├── clock.vh       //   parameterized clock + sync-reset generators
│       ├── dut.vh         //   reg-map, DUT instance, CPU BFM tasks + sequences
│       ├── sti_<iface>.sv //   CPU-controllable stimulus driver per data iface
│       ├── sco_<iface>.sv //   CPU-controllable scoreboard per stream output (optional)
│       ├── tb_<name>.sv   //   self-checking testcases (CPU-bus only)
│       ├── tc_list.md     //   testcase index with status
│       └── sim/<tc>/      //   disposable build dirs (compile/elaborate/sim logs)
├── issue/                 // failure reports and debug reports
│   └── <ip_name>/
│       ├── issue_NNN_<tcname>.md   // failure context (vtestrun)
│       ├── debug_NNN_<tcname>.md   // root cause diagnosis (vdebug)
│       ├── run_summary.md          // overall pass/fail count
│       └── debug_summary.md        // root cause grouping across issues
├── synth/                 // synthesis outputs generated by vsynth
│   └── <module>/
│       ├── vsynth.tcl     // Vivado synthesis script
│       ├── utilization.rpt
│       ├── timing_summary.rpt
│       ├── power.rpt
│       └── synth_report.md
└── prj/                   // simulation and synthesis project files
```

- Every module in `./rtl` must have a corresponding `./doc/<module>.md`.
- Every module in `./lib` must include a `<module>.md` in the same folder.
- Per-module requirement files live in `./ddoc/<module>_req.md` (the module name is the base name with the `_req` suffix removed).
- Design proposals live alongside the requirement files: `./ddoc/<module>_proposal.md`.
- Design documentation for other work to reference lives in `./doc/<module>.md`.
- The top-level integration skeleton `./rtl/<ip>_top.v` is owned by `varch`. `vdesign` generates submodule backbones `./rtl/<module>.v` only and must never create or overwrite `<ip>_top.v`.

## Design Workflow

```
ip_req.md
  │
  ├─[varch]──► ddoc/<submodule>_req.md  (one per submodule)
  │            rtl/<ip>_top.v           (instantiation skeleton)
  │
  ├─[vdesign]─► rtl/<module>.v          (backbone with //@ directions)
  │             ddoc/<module>_proposal.md (architecture + algorithm)
  │             doc/<module>.md         (module documentation)
  │
  ├─[vfill]──► rtl/<module>.v           (complete implementation)
  │            tb/<module>/             (testbench + simulation)
  │
  ├─[vflow]───► flow_status.md          (live phase-completion snapshot)
  │
  ├─[vsynth]──► synth/<module>/vsynth.tcl        (synthesis script)
  │             synth/<module>/synth_report.md   (utilization, Fmax, power)
  │
  ├─[vtestgen]► tb/<ip>/{Makefile,script/,clock.vh,dut.vh} (bench project)
  │             tb/<ip>/sti_<iface>.sv          (CPU-controllable stimulus drivers)
  │             tb/<ip>/tb_<name>.sv            (self-checking testcases, CPU-bus only)
  │             tb/<ip>/tc_list.md              (testcase index)
  │
  ├─[vtestrun]► issue/<ip>/issue_NNN_<name>.md   (per-failure reports)
  │             issue/<ip>/run_summary.md        (overall pass/fail summary)
  │
  ├─[vdebug]──► issue/<ip>/debug_NNN_<name>.md  (root cause diagnosis)
  │             issue/<ip>/debug_summary.md      (batch: root cause grouping)
  │
  └─[vdoc]────► doc/<ip>.md             (full IP integration document)
```

## Available Skills

| Skill     | Purpose |
|-----------|---------|
| `varch`   | Decompose an IP requirement into submodules; generate per-module `ddoc/` requirement files and a top-level skeleton |
| `vdesign` | Generate a design proposal, module documentation, and RTL backbone with `//@` directions from a requirement file |
| `vfill`   | Implement the Verilog code from an approved proposal, then lint and simulate |
