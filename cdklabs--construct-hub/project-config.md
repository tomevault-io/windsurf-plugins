# AGENTS.md — construct-hub

> Contributor-focused guide for AI agents working on the construct-hub codebase.

Last synced: 2026-05-28

## Overview

`construct-hub` is a CDK L3 construct that provides the building blocks for a self-hosted construct documentation site. [constructs.dev](https://constructs.dev) is one deployment of it; organizations can deploy their own. The deployment for `constructs.dev` lives in a separate, non-public repo — this repo is just the construct. It is published to npm as `construct-hub` and built with [jsii](https://github.com/aws/jsii) — every export under `src/` is part of the public API surface and must be jsii-compatible (Python/Java/.NET bindings are generated from TypeScript). The project is `experimental` (per `package.json`); breaking changes are technically allowed but additive changes are strongly preferred. The repo is managed by [projen](https://github.com/projen/projen) — `package.json`, `tsconfig.json`, and most build/CI scripts are generated from `.projenrc.ts`. See [CONTRIBUTING.md](./CONTRIBUTING.md) for the contributor guide and [docs/application-overview.md](./docs/application-overview.md) for system architecture.

## Quick Reference — Commands

| Task | Command |
|------|---------|
| Compile only (writes `lib/`) | `yarn compile` |
| Full build (bundle → compile → test → docgen → package) | `yarn build` |
| Incremental compile | `yarn watch` |
| Run all tests (jest + eslint + integ assertions) | `yarn test` |
| Single jest test | `yarn compile && npx jest lib/__tests__/<path>.js -t "<test name>"` |
| Lint | `yarn eslint` |
| jsii API compat against published version | `yarn compat` |
| Bundle one lambda/ECS handler | `yarn bundle:<name>` (e.g. `bundle:ingestion`) |
| Bundle all handlers | `yarn bundle` |
| Synthesize dev-app | `yarn dev:synth` |
| Deploy dev-app to current AWS account/region | `yarn dev:deploy` |
| Diff dev-app vs deployed | `yarn dev:diff` |
| Destroy dev-app | `yarn dev:destroy` |
| Hotswap dev-app | `yarn dev:hotswap` |
| Regenerate projen-managed files | `npx projen` |

> **Note:** Tests run from compiled `.js` under `lib/__tests__/`, not `src/__tests__/`. Run `yarn compile` (or `yarn build`) before any `jest` invocation, or test files won't exist.

## Your Role

You are a `construct-hub` contributor. This repo is the **construct** — a CDK library. [constructs.dev](https://constructs.dev) and any self-hosted instances are **deployments** of it that live in other repos. Your work serves every deployment, not just one.

Principles:

- **Don't break customer code.** The package is `experimental` (per `package.json`), but every export in `src/` is part of the jsii public API. Treat additive changes as the safe default.
- **Don't edit projen-managed files by hand.** `package.json`, `tsconfig.json`, GitHub workflows, most scripts. Edit `.projenrc.ts` and run `npx projen`.
- **Don't edit generated code.** `lib/` is compiled output. Lambda/ECS sibling files (e.g. `ingestion.ts` next to `ingestion.lambda.ts`) are projen-generated. Edit the source, regenerate.
- **Authoritative references:** `CONTRIBUTING.md` for workflow, `docs/application-overview.md` for architecture, `docs/operator-runbook.md` for ops behavior.
