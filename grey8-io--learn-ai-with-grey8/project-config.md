# CLAUDE.md — AI Assistant Context

## Project Overview

**Learn AI With Grey8** is a self-driving, open-source AI bootcamp powered by a local LLM tutor. Learners build 15 real projects across 12 progressive phases — from Python basics to deploying AI agents — with zero cloud API keys required. A Socratic AI tutor (running locally via Ollama) guides learners, grades exercises, and provides progressive hints.

Licensed under AGPL-3.0.

### Tech Stack

- **Frontend:** Next.js 14 (App Router, Tailwind CSS, dark-mode default) — `platform/web/`
- **Backend:** FastAPI (async, Python 3.11+) — `tutor/`
- **LLM:** Ollama running llama3.2:3b locally — port 11434
- **Database/Auth:** Supabase (Postgres + GoTrue auth, local Docker) — port 54321 (optional — app works without it)
- **Progress:** Dual-layer persistence — localStorage (anonymous) + Supabase (signed-in) — `lib/progress/`
- **Content Engine:** ACE framework (Click CLI, sync/generate/curate/reflect) — `ace/`
- **Infrastructure:** Docker Compose — `docker/`

### Monorepo Structure

```
curriculum/       Lesson content (Markdown, exercises, quizzes) — files in git, not DB
tutor/            FastAPI tutor engine (chat, grading, hints via Ollama)
platform/web/     Next.js 14 frontend (App Router, Tailwind, progress persistence)
platform/supabase/ Supabase migrations and config (auth, progress tables with RLS)
ace/              ACE framework CLI (generate, curate, sync, reflect)
docker/           Docker Compose files and Dockerfiles
docs/             Documentation site (Docsify — course guide, getting started, contributing)
projects/         15 capstone project starters
local-dev/        Local dev scripts (Ollama setup, etc.)
scripts/          Setup and automation scripts
```

## Architecture

```
Next.js :3000  ──REST──►  FastAPI :8000  ──Ollama API──►  Ollama :11434 (llama3.2)
    │                         │
    └────────────►  Supabase :54321 (Auth + Postgres)  [optional]
    │
    └────────────►  localStorage (anonymous progress)
```

- **Frontend calls backend only.** Next.js never calls Ollama directly — all LLM requests go through FastAPI `/api/` proxy routes.
- **Content is files in git, not database.** The tutor engine reads curriculum content from disk via `curriculum_path` config. The platform serves content through a content API that reads `manifest.json`.
- **`manifest.json` is the source of truth** for the platform. It is auto-generated by `ace sync` from the files on disk. Never edit it manually.
- **URL encoding convention:** lesson IDs like `phase-01/lesson-01` become `phase-01--lesson-01` in URLs (slash replaced with double-dash).
- **Progress persistence is dual-layer.** Anonymous users get localStorage persistence (survives refreshes and restarts). Signed-in users get Supabase database persistence with RLS. On sign-in, localStorage data auto-migrates to the database.
- **Auth is optional.** The middleware allows anonymous access to all `/learn/*` routes. Supabase is only required for multi-user/enterprise setups.

## Key Conventions

### Curriculum

- Every lesson lives under `curriculum/phase-NN-slug/lesson-NN-slug/`
- Required files per lesson:
  - `content.md` — lesson text (~800-1000 words)
  - `exercises/ex-01/starter/main.py` — starter code with TODOs
  - `exercises/ex-01/solution/main.py` — complete working solution
  - `exercises/ex-01/tests/test_exercise.py` — pytest tests
  - `exercises/ex-01/rubric.md` — grading criteria for AI + test grading
  - `exercises/ex-01/hints.json` — array of exactly 3 progressive hints
  - `quiz.json` — multiple-choice questions (4 options each, zero-indexed correct answer), scaled by difficulty: 5 (Phase 1-3), 7 (Phase 4-7), 10 (Phase 8-12)
- Schema defined in `curriculum/schema.json`
- Manifest at `curriculum/manifest.json` is auto-generated — **NEVER manually edit it**
- After any curriculum file change, run `ace sync` to update manifest + README table
- Lesson IDs follow the pattern `phase-NN/lesson-NN` (validated by schema regex)
- Exercise difficulty must be one of: `easy`, `medium`, `hard`
- Diagrams in `content.md` use ````mermaid` code blocks for flowcharts/architectures (rendered as SVG on the platform) and plain ``` code blocks for text-based visuals (tables, bar charts, scatter plots, code annotations)
- Mermaid diagrams are semantically colored by node content — see color standard below

### Python (tutor/, ace/)

- Python 3.11+, managed via `pyproject.toml` in each package
- **tutor engine:** async/await everywhere (FastAPI + httpx for Ollama calls)
- **ace CLI:** synchronous code (Click CLI with Rich console output)
- Install deps: `pip install -e ".[dev]"` in each directory (not `pip install -r requirements.txt`)
- Linting: `ruff check .` — Formatting: `black .`
