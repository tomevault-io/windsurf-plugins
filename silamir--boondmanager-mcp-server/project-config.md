# CLAUDE.md - BoondManager MCP Server

## Project Overview

MCP (Model Context Protocol) server for the BoondManager API. Exposes
**238 tools, 24 prompts, 48 resources, 6 resource templates** across 42
domains, allowing Claude to interact with BoondManager ERP/CRM data. The exact catalogue is
auto-generated in `TOOLS.md` (regenerated by `npm run docs:tools`); the figures
above are asserted against a real client by `src/catalogue-counts.test.ts`.

- **Language**: TypeScript (strict mode), ES2022, Node16 module resolution
- **Runtime**: Node.js >= 22 (Node 20 is EOL since 2026-04-30)
- **Transports**: stdio (default, no network port) and Streamable HTTP (for gateways/remote)
- **MCP spec level**: `2025-11-25` (see *MCP spec level* below)
- **API format**: JSON:API (BoondManager REST API)
- **License**: Apache-2.0 (see `LICENSE`, `NOTICE`)

## MCP Spec Level

- **Negotiated**: whatever the installed SDK advertises. `@modelcontextprotocol/sdk@1.30.0`
  has `LATEST_PROTOCOL_VERSION = '2025-11-25'`, so that is the revision the server
  speaks (the transport does not pin a version of its own).
- **Features used from `2025-11-25`**: server-level `instructions`
  (`src/instructions.ts`), `Implementation.description`, `Origin` header
  validation → `403` (`src/transports/http.ts`), `icons` on tools/prompts/
  resources (SEP-973, `src/icons.ts`), titled single-select enum + default in
  the delete elicitation (SEP-1330/SEP-1034, `src/tools/crud-factory.ts`),
  self-correctable argument-validation errors (SEP-1303,
  `src/tools/validation-wrapper.ts`).
- **Current published revision**: `2026-07-28` — not adopted yet. What is (and
  isn't) worth adopting from it is tracked in
  [issue #170](https://github.com/silamir/boondmanager-mcp-server/issues/170).
- Keep this section honest when the SDK is bumped: the SDK's
  `LATEST_PROTOCOL_VERSION` is the only source of truth for what is negotiated.
- **Minimum SDK is `^1.30.0`** (`package.json`, issue #246): the features
  listed above (`ResourceTemplate`, the titled elicitation enum, the 2025-11-25
  negotiation) do not exist in 1.29, so a looser range would let `npm install`
  resolve a version the code does not run on.

## Server Identity & Instructions

`createMcpServer()` advertises three things at `initialize`:

- `name` (`SERVER_NAME`) and `version` (`SERVER_VERSION`, read from `package.json`)
- `description` (`SERVER_DESCRIPTION`, also read from `package.json` — deliberately
  *not* a fifth hardcoded string to sync at release time)
- `instructions` (`SERVER_INSTRUCTIONS`, `src/instructions.ts`)

`src/instructions.ts` holds **cross-cutting rules only** — tool naming, the
perimeter filter gotchas, the `keywords` prefix syntax, pagination/`fields`
token economy, and dictionary resolution via `boond://dictionary/*`. It exists
so those rules are stated **once** instead of once per tool description (182
tools × boilerplate is paid on every turn). Per-tool specifics stay in the tool
descriptions and `src/schemas/index.ts`.

Length is capped at `MAX_SERVER_INSTRUCTIONS_LENGTH` (4000) and asserted in
`src/tools/descriptions.test.ts` — the instructions compete with the tool
catalogue for the same context budget.

## Commands

```bash
npm run build               # TypeScript compilation (tsc)
npm run dev                 # Watch mode (tsc --watch)
npm start                   # Run server (node dist/index.js)
npm test                    # Run all tests (vitest run)
npm run test:coverage       # Tests + V8 coverage, fails under the per-folder / per-file thresholds (see Testing)
npm run lint                # ESLint
npm run lint:fix            # ESLint with auto-fix
npm run typecheck           # tsc --noEmit
npm run docs:tools          # Regenerate TOOLS.md from server registrations
npm run docs:tools:check    # Fail if TOOLS.md is stale (used in CI)
npm run plugin:manifest       # Regenerate the Claude Code plugin files from manifest.json
npm run plugin:manifest:check # Fail if they are stale (used in CI)
```

Run a single test file:
```bash
npx vitest run src/tools/candidates.test.ts
```

## Architecture

```
src/
├── index.ts              # Entry point: initClient(), selects transport (stdio or http) via MCP_TRANSPORT
├── server.ts             # createMcpServer() factory — instantiates McpServer (name/version/description + instructions) + registers tools/prompts/resources
├── instructions.ts       # SERVER_INSTRUCTIONS — cross-cutting usage rules sent once at initialize
├── icons.ts              # DOMAIN_ICONS (SEP-973) + installProtocolIcons() — decorates tools/list & prompts/list responses
├── schema-dialect.ts     # installSchemaDialectCompat() — strips the SDK's draft-07 `$schema` from advertised input/outputSchema
├── constants.ts          # DEFAULT_BASE_URL, pagination limits, API_PATHS, ENTITY_TABS
├── types.ts              # JsonApiResource, JsonApiResponse, BoondConfig, SearchParams
├── transports/
│   └── http.ts           # startHttpTransport() + resolveHttpOptions() — MCP Streamable HTTP server + GET /healthz (liveness, non authentifié)
├── services/
│   ├── boond-client.ts   # Barrel — the ONLY path tools, transports, resources and test mocks import from. Implementation below (issue #239)
│   ├── http/
