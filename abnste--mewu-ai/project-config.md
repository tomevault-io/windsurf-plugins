# 喵呜AI 开发约束
- 当前维护分支为 `master`；不要自动创建或推送以 AI 工具名命名的开发分支。
- 项目自有源代码正式采用 MPL-2.0。新 C#/XAML 源码保持 SPDX 标识，根 LICENSE 必须保持 Mozilla 官方协议原文；SOURCE.md、双语 README 与关于页须一致说明允许合规商用、对外分发时提供受覆盖源码并保留声明，不得恢复“商用必须另行授权”或添加强制通知/界面署名条件。第三方条款保持独立，后续发布包必须携带 LICENSE 和 SOURCE.md。依赖禁用 GPL/AGPL 的开发约束不改变标准 MPL 的条款。
- 解决方案 `.slnx` 必须显式声明 x64 平台，并为主程序、测试和 ProviderSmoke 映射 `Platform Project="x64"`；只改 csproj 不能阻止解决方案构建下传 AnyCPU。根目录 `dotnet build -c Release --no-restore -warnaserror` 必须可用。
- Windows-only，保持 C#、WPF 与现代 .NET，不迁移到其他 UI 技术。
- Capture 与 Presentation 分层；离线基础能力不得依赖 AI。
- `app.manifest` 必须保持 `PerMonitorV2` DPI 感知；核心区域统一使用虚拟桌面物理像素，正确处理多屏、负坐标和混合 DPI。
- WPF DIP 与截图物理像素之间的换算统一放在 `ScreenCoordinateService`，不要在窗口业务代码内重复计算比例。
- AI Provider 与 UI 解耦；用户明确发送前不得上传屏幕内容。
- 不提交密钥、`.env`、用户配置、日志、临时截图或录屏。
- 禁止 GPL/AGPL；优先微软官方、MIT、BSD、Apache-2.0。
- 重大修改必须构建和测试，仓库始终保持可运行、可回滚。
- 区域 MP4 使用 MIT 的 ScreenRecorderLib + Windows Media Foundation；不要改为捆绑 GPL FFmpeg。
- .NET 10 WPF `GifBitmapEncoder` 会把帧延迟写成 0；GIF 导出后必须按 GIF 块结构校正 Graphic Control Extension，并用解码测试验证播放时长。
- 产品默认使用 `NativeMethods.ExcludeFromCapture` 防捕获。用户明确开启持久化 `TeachingMode` 后，下次截图覆盖层、它创建的贴图/贴视频及原位颜色/保存对话框通过独立 `ApplyPresentationCaptureVisibility` 允许教学共享；设置和凭据窗口不得受该设置影响。模式在覆盖层创建时固定，避免录制中途切换策略；演示模式阻止自带区域录屏和长截图。Debug 的 `MEWU_QA_CAPTURE_WINDOWS=1` 仅供自动化验收，Release 必须继续编译掉该环境开关，不能让它改变任何窗口的保护。
- 全屏截图根画布必须保持 `Background="Transparent"` 才能接收空白区域命中；拖选期间鼠标必须由 `Root` 捕获和释放，不能由窗口捕获后让挂在根画布上的移动/松开事件断路。
- InkCanvas 的画笔可使用 `FitToCurve`，矩形和箭头等几何标注必须在生成 Stroke 时关闭曲线拟合，否则直角和箭头轮廓会被平滑变形。
- 默认 AI Provider 固定为 MiniMax M3：国内 OpenAI-compatible 地址 `https://api.minimaxi.com/v1`，模型 ID `MiniMax-M3`。M3 原生接受 `image_url` 与 `video_url`，图片单张最大 10 MB，URL/Base64 视频单文件最大 50 MB、整个内联请求体最大 64 MB，视频抽帧率范围 0.2–5 FPS；50 MB 原视频经 Base64 展开会超过请求体上限，必须提前提示压缩至约 47 MB 或改用 Files API 的 `mm_file://` 引用。不得自动回退或重新默认到火山方舟。
- 所有 OpenAI-compatible 内联多模态请求最多 16 个附件、序列化请求体最多 64 MiB；读取文件和 Base64 编码前必须用原始字节数与 JSON/Base64 上界提前拒绝。Provider 能力需分别公开图片和视频单体上限，不能再用一个最大值误导截图编码策略。
- 发送给 Provider 的历史上下文最多 20 条消息、24,000 个 UTF-16 字符，只保留至多一条系统消息和最近的完整“用户—助手”问答对；不得恢复无限历史、孤立回复或未完成的单边消息。
- UI 编码生成的截图附件 `byte[]` 属于敏感屏幕内容，必须明确所有权；批量编码中途失败或取消时清零已生成的全部缓冲，Provider 请求结束后也要清零附件字节，不能只清序列化请求体。
- 屏幕 AI 的产品形态不是把选区截图搬进普通窗口：应保持全屏覆盖层，冻结原桌面作为背景，把选区、发光边框、归一化批注连线和回答/输入卡放回原屏幕坐标；用户点击 AI 即代表明确发送并应自动开始分析。
- 屏幕助手唤醒阶段只显示底部对话条；拖选、移动、缩放或鼠标进入选区时对话条向下收纳，工具栏在选区上下自适应并避开对话条。AI 回答区域只能在首个回复内容到达后展开；从选区层进入回答层时必须复用最初的干净桌面帧，不能再次截图把旧覆盖控件冻结进背景。
- 屏幕助手的输入、分析状态和回答必须始终是同一个覆盖层里的同一条对话控件原地伸展，严禁关闭覆盖层后再创建独立 AI 对话窗口。覆盖层支持连续多区域框选、编号、删除和移动缩放，并把所有区域作为多张视觉输入发送；AI 批注用从 0 开始的 `regionIndex` 映射回对应区域。
- 选区工具条必须与底部对话条保持统一的浅色圆角纯图标风格；第一个按钮固定为引用当前区域，不得恢复成直接调用 AI。
- 区域引用以输入条内可点击、可移除的 `@区域N` 标签呈现；引用必须绑定区域对象而非普通字符串或可变编号，删除和重排区域时同步更新标签，发送和 AI 批注映射均以实际引用对象为准。
- UI 布局和避让算法必须保证有限次结束；坐标触及边界后不得继续使用值不再变化的无界 `while` 循环，空间不足时应选择有界的最优回退位置。
- 标注、录屏控制和录制完成预览必须留在唯一全屏覆盖层的原选区位置，严禁恢复 `DrawingWindow`、`RecordingControlWindow` 或 `RecordingPreviewWindow` 等独立弹窗。录制结果作为绑定视频对象的 `@视频N` 引用，可保存、复制、原位贴视频，并允许继续框选其他截图区域。
- OCR 文字选择必须在每个区域内使用单一文档控件以支持跨行连续选择；Esc 的取消/退出处理优先级必须高于文字控件自身按键处理，不能被只读编辑控件吞掉。
- 火山方舟 Agent Plan 的翻译请求必须显式关闭深度思考，并使用流式 Chat Completions、独立超时和 JSON 完整性提前终止条件；其兼容流可能已返回完整正文但迟迟不结束，不能依赖服务端结束标记让原位翻译永久停在“接收中”。
- 区域录屏开始后截图覆盖层必须继续显示暗化遮罩和当前区域边框，并依赖防捕获让遮罩不进入成片；录屏控制窗结束后再关闭覆盖层。
- 贴图默认按选区的原物理像素位置和大小显示，阴影放在额外透明边距内；双击取消置顶，右键菜单需使用全局浅色菜单样式。
- 截图覆盖层中的 OCR 和翻译不得关闭覆盖层或新开结果窗口。OCR 必须保持原截图视觉不变，仅建立透明文字命中层，让用户按字符拖选、Ctrl+C 或右键复制；不得再绘制可见文本框。翻译使用 OCR 像素坐标缩放到对应选区，在冻结桌面的原位置逐行显示译文。两者都必须保留选区、工具条和底部对话条。
- OCR 默认使用随软件离线交付的 PP-OCRv6 Small 多语言模型，通过 RapidOcrNet/ONNX Runtime 识别并返回字符位置；初始化或推理失败时才降级到 `Windows.Media.Ocr`，界面状态必须明确显示实际引擎。
- AI 流式回调必须绑定创建它的请求实例；请求完成、取消或被新请求替换后不得再接收迟到增量。最终思考内容以 Provider 返回值为准，成功、取消和失败都必须停止动画并自动折叠；正文为空或只有思考内容时按失败处理，不得显示“完成”、写入历史或渲染批注。
- 结构化 AI 回答优先严格解析 JSON；只有当整段回复明确是根对象或 JSON 代码块且含根 `answer` 字段时，才允许从损坏或截断的结构化响应中容错提取正文。普通正文里的 JSON 片段必须原样保留，`annotations: null`、数组内 `null` 或损坏的批注均按无批注处理。
- 当前发布形态是无 MSIX 身份的桌面 WPF EXE，语音输入使用微软 `System.Speech` 桌面 SAPI；不得改回要求 package identity 的 `Windows.Media.SpeechRecognition`，除非发布流程同时提供并验证包身份。缺少麦克风、语言识别器或音频设备时必须显示可操作的中文提示。
- 发布视频理解前必须在 Release 覆盖层走通“区域录屏 → 自动生成 `@视频N` 引用 → 原位发送 → 语义回答”闭环；核对成片时长与发送前后哈希不变，并抽查首、中、末帧确认画面无遮罩、选区框或录制控件。
- 覆盖层中文本框或 OCR 文档控件拥有焦点时，必须隔离 C/S/P/D/T/O/R 等全局快捷键；Esc 仍由窗口预览阶段优先处理。
- 隐式全屏区域不得因用户只输入文字而自动创建或发送；只有用户显式选择截图、录屏或上传附件时才发送视觉内容。无视觉附件的请求保持纯文字对话，Hermes 继续使用同一 Profile 的持续上下文；一旦产生显式选区，引用、发送和批注映射都必须彻底排除隐式全屏区域。
- 解析 SSE 时必须先消费当前事件的正文与思考增量，再处理同一事件里的 `finish_reason`；结束标志不得吞掉最后一段正文。
- SSE 只有收到 `[DONE]`、非空 `finish_reason`，或调用方的完整性谓词确认结构化正文已经完整时才算成功；连接自然 EOF 但未完成必须按截断失败，严禁把半段正文写入历史或让 Smoke 误判通过。
- MiniMax 兼容流的 `content` 与 `reasoning_details[].text` 可能返回累计全文，UI 只能转发相对上一块的新增后缀；普通 OpenAI-compatible Provider 的增量正文仍须按片段追加，不能全局套用同一种语义。
- MiniMax M3 的长多模态流偶尔会在句段边界重新开始累计块；非前缀块必须作为续段并按“已有后缀—新块前缀”的最长精确重叠去重，不能把它当整段替换，否则最终答案会丢失开头主语。
- PP-OCR 返回 0 行是合法空结果，不得因此降级 Windows OCR；只有初始化或推理异常才允许降级，并要向界面报告实际引擎。
- GIF 只在用户保存时从最终 MP4 按需抽帧生成；严禁恢复录制期间 `CopyFromScreen`、PNG 帧目录或其他重复捕获链，导出不得修改源 MP4。
- GIF 导出必须同时限制帧数、单帧尺寸和全部解码帧的总像素预算；长视频应保留覆盖完整时长的采样帧，通过动态缩小分辨率控制内存峰值。
- 冻结虚拟桌面时应从 `Bitmap.LockBits` 像素缓冲直接创建已冻结的 WPF 位图，严禁恢复整桌面 PNG 编码再解码；OCR 输入也应优先直接复制 BGRA 像素，避免无意义的图片压缩往返。
- 覆盖层防捕获启用失败，或 Debug 视觉验收开关主动绕过防捕获时，必须阻止区域录屏，不能冒险把遮罩和控件录入成片。
- 停止录屏必须有有限超时；录制器不返回完成/失败回调时，覆盖层要自动退出“处理中”并异步释放会话。截图区域成功转换为视频后必须清除并隐藏原 OCR、翻译、AI 批注和手绘层，失败时才恢复原图层。
- AI 请求取消、替换、窗口关闭或流结束后必须拒绝所有迟到增量和最终结果，写入内存/磁盘历史前也要再次校验请求身份与取消状态。
- 对话历史在取得并发写锁后必须再次检查取消状态；单条 JSONL 一旦开始落盘则必须完整写完，不能因中途取消留下半行损坏记录。
