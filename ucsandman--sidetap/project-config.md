# SideTap

LLM agents drive a real iPhone from Windows over USB + WebDriverAgent (go-ios).
Windows rebuild of ShawnPana/phone-harness (which is macOS-only).

## Architecture

- `src/phone_harness/wda_client.py` — thin HTTP client for WebDriverAgent (:8100). requests only. Kill switch: a `.state/STOP` file blocks every action POST at the `_request` chokepoint (perception GETs keep working). The same chokepoint appends every successful action POST to `.state/agent_activity.log` (bounded ring; typed text NEVER recorded, only char counts — it can be a passcode). WDA holds exactly ONE session and creating a new one evicts the holder, so every client shares the id published in `.state/wda_session`: adopt it, heal an unusable id by adopting the replacement or minting fresh. "Unusable" covers "invalid session" AND the `point.x != INFINITY` state — a session that crosses a screen lock keeps answering GETs but fails every /actions forever (bit the Unlock button live; a test pins the heal). The session creator applies the post-gesture waits from config (WDA_IDLE_WAIT=2, WDA_ANIM_COOLOFF=0 — the cool-off default of 2 cost 2-5s per swipe under scroll momentum; ~0.7s with it at 0, measured on device).
- `src/phone_harness/trust.py` + `approval.py` — prompt-injection defense. `trust` holds the sticky process taint flag (set by `ui_tree`/`screenshot`/`read_messages`; `trust.internal()` keeps a helper's own bookkeeping reads from counting), the heuristic scanner (flags are a SIGNAL for the human card, never an allow/deny — no filter detects injection reliably), and the data-not-instructions envelope the MCP layer wraps screen reads in. `approval` is the `.state/pending_send.json` handshake that blocks `send_message` until the viewer answers; fail closed, timeout means deny, one card at a time. `approval.mode()` is the always/flagged/off setting, read at SEND TIME (not import) because the human flips it mid-session in a different process: `.state/send_approval` (viewer toggle) beats `SEND_APPROVAL` in `.env`, and anything unrecognized falls back to `always` — a setting that cannot be read must never be the one that disables the gate. `set_mode` is deliberately absent from `_TOOLS`, `_ACT_TOOLS` and `helpers.__all__`, and a test pins that. `send_message` gains NO bypass argument on purpose — every parameter of an MCP tool is reachable by an injected instruction — so the viewer's own `/api/text` uses the thread-local `trust.human_initiated()` instead (it also holds `_ACTION_LOCK`, so gating there would freeze every viewer gesture for the whole timeout). `type_text` refuses PHONE_PASSCODE; `unlock()` drives the client directly and is unaffected. The MCP reading tools must be registered AFTER their `__doc__` is extended: FastMCP reads the docstring at registration, not at call time.
- `src/phone_harness/device.py` — go-ios wrapper; detached tunnel/runwda/forward processes, pids+logs in `.state/`. `ios_path()` falls back to `%APPDATA%\npm\ios.exe` when PATH lookup fails — Windows truncates a >4095-char registry PATH in the logon environment, so shortcut/Startup launches can miss the npm dir (bit the Startup shortcut live; a test pins the fallback). `detect_wda_bundle()` caches its hit in `.state/wda_bundle` because deep sleep EMPTIES `ios apps --list` while the app is still installed (seen live); `lockdown_ready()` (`ios date` exit code) is the "has the human woken the phone" probe — deep sleep gates lockdown (ReadPair errors) while tunnel services keep working. `ddi_mounted()`/`mount_ddi()`: an iOS UPDATE silently unmounts the Developer Disk Image, and without it testmanagerd refuses every test session — runwda dies in dtx channel timeouts that look like a broken tunnel (bit live 2026-08-10); mounting needs the phone UNLOCKED (DeviceLocked otherwise), so `up()` auto-mounts and the doctor names it.
- `src/phone_harness/admin.py` — `doctor` (ordered checks, each names its fix; the STOP kill switch is checked FIRST, then LAN exposure and the 7-day signature countdown), `up` (serialized by `_UP_LOCK`: launch.py's background bring-up and the viewer's Restart link can overlap), `down`, `notify-expiry` (Windows toast when <36h remain on the signature; `--install` registers a daily 10:00 scheduled task via phone-harness.cmd — renewal itself always needs one Sideloadly click, Apple auth mints the profile).
- `src/phone_harness/capture.py` — screenshots. Prefers WDA's HTTP `/screenshot` (sessionless client, cannot steal the one WDA session) with a 10s back-off; falls back to the `ios screenshot` subprocess, which is the only path that works before signing.
- `scripts/lock_ports.ps1` — self-elevating firewall rule blocking LAN access to :8100/:9100 (WDA has no auth). Fired by the viewer's Lock ports button or run by hand.
- `src/phone_harness/signing.py` — `fix-input`: builds a p12 from Sideloadly's cert, captures the profile Sideloadly mints (Temp watcher), re-signs WDA incl. the nested `.xctest` via `ios sign app`. All local; no Apple auth.
