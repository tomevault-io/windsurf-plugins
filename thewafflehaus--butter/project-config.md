# Butter

Apple Silicon LLM inference built on pre-compiled Metal kernels generated by the sibling [`iron`](https://github.com/thewafflehaus/iron) Rust DSL.

Global dev conventions (planning, issues, git workflow, testing, performance, code quality) live in `~/.agents/AGENTS.md`. This file covers Butter / Apple-platform / iron specifics only. For anything user-facing, the Butter [`documentation/`](documentation/README.md) tree is the source of truth — DO read it progressively, DO NOT re-derive it.

## Build / test / bench / profile

- Local loop: `make regenerate-kernels` then `make build`.
- **DO go through `make` for tests; DO NOT run bare `swift test`.** Each `Tests/ModelTests/*` suite loads multi-GB HuggingFace snapshots; parallel runs pin the GPU and OOM the box.
  - `make test-unit` — `ButterTests` + `IronSwiftTests` (fast, parallel-safe).
  - `make test-integration` — `ModelTests`, serialized (`--num-workers 1`).
  - `make test` — both in sequence; the full local CI gate.
  - `make coverage` — unit-suite coverage. Line coverage SHOULD stay ≥ 80 %.
  - `make test-stress` — production cap, uncapped parallelism; DO run it after touching dispatch code.
- After `make regenerate-kernels`, DO run the empty-body MSL detector (documented in iron's `developing.md`) over `Sources/IronSwift/Resources/kernels/*.metal`. A hit ships all-zeros output and is a release blocker.
- Longer-form testing story: [`documentation/developing/testing.md`](documentation/developing/testing.md).

### Porting kernels from our `ekryski/mlx` fork

Custom kernels (turbo / gated-delta / SSM / …) live on **`ekryski/mlx@alpha`** under `mlx/backend/metal/kernels/` (local checkout `~/Development/personal/ai/mlx`, branch `alpha`). iron's `MLX_COMMIT` is pinned there so `iron bench` has a side-by-side reference.

- DO try existing iron DSL primitives + `#[kernel]` macros first.
- Missing a primitive? DO extend the DSL (body parser → IR → MSL codegen). DO NOT hand-write raw MSL.
- New AURA / GDN / SSM / vision / audio kernels DO start under `crates/iron-std/src/butter/`; graduate to `mlx/` once an MLX counterpart ships at the pinned commit.
- After each port, DO diff the iron-generated MSL against the `alpha` reference kernel.

### Wrapping a kernel in a Swift `Ops` function

An `Ops` wrapper is the boundary between caller-supplied dimensions and the GPU. For **reduction-mode kernels** (`simd_*` / `threadgroup_alloc` / `KernelMode::Reduction` in the `.rs`, or a fixed `tpg=` in the `BenchSpec`) it is the only thing enforcing the geometry contract the kernel can't check at runtime:

1. DO read the kernel's `## DISPATCH INVARIANTS` block. If it has none, DO add one in the same commit.
2. DO `precondition` every invariant at the top of the wrapper, before any allocation or dispatch. Cite the kernel `.rs` in the message.
3. DO derive dispatch geometry from the invariants. DO NOT use `elementwiseGrid` for a reduction kernel — that is the canonical freeze bug; it is for genuine one-thread-per-output Grid3D kernels only.
4. DO add a `Tests/ButterTests/OpsTests.swift` test exercising the wrapper at a production-realistic shape.

### Testing — Butter side

DO ship a paired GPU correctness test in the same commit for every non-trivial `butter/` or `mlx/` kernel (test layers: `docs/testing.md`). What Butter tests in Swift:

- **Per-Op** — `Tests/ButterTests/Ops*Tests.swift`: every `Ops.<fn>` against a small asserted output. New Ops DO land with a test.
- **Per-cache** — `Tests/ButterTests/*StateCacheTests.swift`: append / slice / serialize round-trip + multi-layer working-buffer sharing.
- **Determinism** — `Tests/ModelTests/DeterminismSmokeTests.swift`: temp=0, same prompt, stable across runs.
