# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`code-organizer` is a VS Code extension (publisher `ran-codes`) that turns comment
patterns like `# Section Name ----` into a navigable outline. Written in TypeScript,
bundled with esbuild.

## 1. Folders

```
code-organizer-vscode/
├── .claude/                     # Claude Code settings: settings.json (shared, committed)
│                                #   + settings.local.json (per-machine)
├── .context/                    # Long-form notes — the docs the glossary points at
│   ├── refactors/               # Refactor plans (src-refactor-1, -2, -3)
│   ├── vs-code-api/             # VS Code API research for the outline-sync work
│   └── workflow.md              # Canonical release checklist (see §5)
├── .github/
│   └── ISSUE_TEMPLATE/
│       └── release.md           # Template for the [Release] v[version] tracking issue
├── .vscode/                     # Editor config: F5 launch, build tasks, recommended exts
├── assets/                      # Everything non-code that is committed
│   ├── images/                  # README screenshots + demo GIF
│   ├── logo/                    # Hex logo (.png + .svg)
│   └── test-files/              # One sample file per supported language (15 files)
├── resources/
│   └── activity-bar-icon.svg    # Icon for the custom Activity Bar container
├── src/                         # All extension source — nothing else compiles
│   ├── test/                    # Mocha suites — one per comment syntax, plus per-module
│   │   └── CLAUDE.md            # Test layout + how to run a single file
│   ├── utils/
│   │   ├── findSections.ts      # THE parser — everything reads through it (see §3)
│   │   ├── getCurrentSection.ts # Cursor offset → deepest containing section (pure)
│   │   ├── sectionTree.ts       # buildChildrenMap() — shared parent→children index
│   │   ├── vscodeHelpers.ts     # sectionRange() — the only vscode-importing util
│   │   └── CLAUDE.md            # Parser contract + how to add a comment style
│   ├── cursorSync.ts            # Cursor→outline sync: debounce, highlight, reveal
│   ├── decorations.ts
│   ├── documentSymbolProvider.ts
│   ├── extension.ts             # activate() — wiring only
│   ├── log.ts                   # "Code Organizer" Output Channel
│   ├── sectionIndex.ts          # One parse per (document URI, version)
│   ├── treeDataProvider.ts
│   └── CLAUDE.md                # Module map + the single-parser invariant
├── test-files/                  # Scratch files for manual F5 testing
├── dist/                        # generated — esbuild bundle (gitignored, ships)
├── out/                         # generated — tsc output for tests (gitignored)
├── esbuild.js                   # Bundler config
├── .vscode-test.mjs             # Points @vscode/test-cli at out/test/**/*.test.js
├── package.json                 # Manifest: commands, views, activation, version
├── CHANGELOG.md · README.md · prd.md
└── CLAUDE.md
```

| Folder | What's in it | Ships in the `.vsix`? |
| --- | --- | --- |
| `src/` | All TypeScript. Four top-level modules plus `utils/` (parser + shared helpers) and `test/`. Edit here. | ❌ (bundled into `dist/`) |
| `src/test/` | Mocha suites — one per comment syntax (hash, double-slash, JSX, md, quarto, sql) plus one per non-parser module (`sectionTree`, `getCurrentSection`, `sectionIndex`, `documentSymbolProvider`, `treeDataProvider`). Compiled to `out/test/` before running. | ❌ |
| `dist/` | esbuild output (`extension.js`). Generated by `npm run compile` / `package`. | ✅ — this *is* the extension |
| `out/` | `tsc` output, tests only. Generated by `npm run compile-tests`. | ❌ |
| `assets/` | Committed binaries and samples: README images, logo, per-language test files. | ✅ (not in `.vscodeignore`) |
| `assets/test-files/` | One `test.<ext>` per supported language (c, cpp, cs, go, java, js, md, mmd, php, py, R, rs, sql, swift, txt). Reference fixtures for what the parser must handle. | ✅ |
| `resources/` | The Activity Bar SVG referenced by `package.json`. | ✅ |
| `test-files/` | Ad-hoc scratch files (`demo.py`, `test.jsx`) for eyeballing behavior in the Extension Development Host. | ❌ |
| `.context/` | Design docs and the release checklist. **`workflow.md` is canonical for releases**; `refactors/` holds the multi-PR refactor plans; `vs-code-api/` holds the API research behind the outline-sync work. Per-issue planning docs are not kept here — the decision record for an issue is its PR and commit messages. | ❌ |
| `.github/` | Only `ISSUE_TEMPLATE/release.md`. No Actions — there is no CI/CD (see §4). | ❌ |
| `.vscode/` | `launch.json` (F5 → Extension Development Host), `tasks.json`, workspace settings. | ❌ |
| `.claude/` | Claude Code settings — `settings.json` is committed and shared; `settings.local.json` is per-machine. Not part of the extension. | ❌ |

`src/` and every folder under it carries its own `CLAUDE.md` (`src/`, `src/utils/`,
`src/test/`) describing that folder and deferring to the ones below it. Read those
before editing code; this file stays at repo level.
