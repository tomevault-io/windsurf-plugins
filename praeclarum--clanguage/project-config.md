# CLanguage

C/C++ compiler, stack-based VM, and native code editor in C#. Targets interactive mobile apps (iOS, macOS, Mac Catalyst). Performance is a primary constraint — the VM runs in 100 kHz loops on iPhones. .NET 9+.

## Build

```bash
dotnet build CLanguage.sln
dotnet test CLanguageTests/CLanguageTests.csproj
```

## Regenerate Parser

The Jay parser generator (C# Yacc) produces `CLanguage/Parser/CParser.cs` from the grammar. Run from repo root:

```bash
cd CLanguage && bash prebuild.sh
```

This compiles `Jay/src/*.c` into the `jay` binary, then runs it on `CParser.jay` with `Jay/skeleton.cs` to produce the generated parser. It outputs the file `CLanguage/Parser/jay_warnings.txt` with any warnings from the grammar (e.g., shift/reduce conflicts).

## Project Structure

```
CLanguage/                  Core library (compiler + VM)
  Parser/                   Lexer, preprocessor, Jay grammar, generated parser
  Syntax/                   AST nodes (expressions, statements, declarations)
  Types/                    Type system (CType hierarchy)
  Compiler/                 AST → bytecode compilation, emit contexts
  Interpreter/              VM execution loop, instruction set, stack frames
  CLanguageService.cs       High-level API: parse, compile, run, colorize
  MachineInfo.cs            Target machine config (sizes, builtins, headers)
  Value.cs                  8-byte union — the fundamental unit of the value stack
CLanguageTests/             xUnit tests
Editor/                     Native text editor (iOS UIKit / macOS AppKit)
Jay/                        Parser generator (C source + C# skeleton)
Samples/                    iOS and Mac sample apps
```

## Pipeline Overview

```
Source code (string)
  → Lexer (Token[])
  → Preprocessor (expanded Token[])
  → CParser (AST: TranslationUnit)
  → CCompiler (Executable with bytecode)
  → CInterpreter (stack-based VM execution)
```

Entry point: `CLanguageService.Compile()` or `CLanguageService.CreateInterpreter()`.

## Parser

### Lexer (`Parser/Lexer.cs`)

Character-by-character tokenizer. Produces `Token[]` with location tracking (document, line, column, index). Handles C comments (`//`, `/* */`), string/char literals, numeric constants, ~40 keywords. Has an `IsTypedef` hook so the parser can feed back typedef names — required because C's grammar is ambiguous without knowing which identifiers are type names.

### Preprocessor (`Parser/Preprocessor.cs`)

Operates on token arrays, not text. Iterative expansion — loops until no changes detected (macro expansions can trigger other macros).

- **`#define`**: Object-like and function-like macros. Stored as `Dictionary<string, Define>` where `Define` holds name, parameters, body tokens.
- **`#include`**: Custom callback `Token[]? Include(string path, bool relative)`. Built-in `stdint.h` returns empty. System headers defined in `MachineInfo.SystemHeadersCode`.
- **`#if`/`#ifdef`/`#ifndef`/`#else`/`#endif`**: Full nesting via depth counter. `#if` expressions are evaluated by compiling them as C code through a `PreprocessorContext` (extends `EmitContext`).
- **Gotcha**: To prevent infinite recursion, a macro's own name is removed from scope during its body expansion.

### Grammar (`Parser/CParser.jay`)

ANSI C grammar (from quut.com) extended with C++ class support (class/struct/union with visibility specifiers, member functions). ~40 token types, standard expression precedence hierarchy. Entry rule: `translation_unit`.

### Generated Parser (`Parser/CParser.cs`)

LALR parser generated by Jay. **Do not edit** — regenerate with `prebuild.sh`. Partial class combined with `CParserImpl.cs`.

### Parser Support (`Parser/CParserImpl.cs`)

Hand-written helpers merged with the generated parser:
- `ParseTranslationUnit()` — main entry, runs lexer → preprocessor → LALR parse.
- `AddDeclaration()` — processes declarations, updates typedef tracking.
- `FixPointerAndArrayPrecedence()` — corrects C's notoriously tricky declarator binding (e.g., `int *p[10]` vs `int (*p)[10]`).
- `ParserInput` adapts token stream to Jay's `yyInput` interface. Tracks typedef set and converts `IDENTIFIER` → `TYPE_NAME` tokens on the fly.

## AST (`Syntax/`)

### Expressions (`Expression.cs` base)

All expressions implement:
- `DoEmit(EmitContext)` — generate bytecode pushing result onto value stack.
- `GetEvaluatedCType(EmitContext)` — return the C type of the expression.
- `EvalConstant(EmitContext)` — compile-time evaluation for const expressions.
- `CanEmitPointer` / `DoEmitPointer()` — for `&expr` (address-of).

Key expression types: `ConstantExpression`, `VariableExpression`, `BinaryExpression`, `FuncallExpression`, `CastExpression`, `ArrayElementExpression`, `MemberFromReferenceExpression` (`.`), `MemberFromPointerExpression` (`->`), `UnaryExpression`, `AddressOfExpression`, `DereferenceExpression`, `SizeOfExpression`.
