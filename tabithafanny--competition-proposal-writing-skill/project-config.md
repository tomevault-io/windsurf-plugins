# Competition Proposal Writing Skill - 比赛计划书写作助手

> **版本**: 2.3.0 | **更新时间**: 2026-03-24
> **核心架构**: 项目主档 → Research补证据 → 分析稿 → 成稿 → Review修订 → 统稿可视化
>
> **五大核心方向**: 持续执行但受控 · 先写厚再收敛 · 少表格多论证 · 章节交付闭环 · 图表升级答辩级

## 自主运行模式（Continuous Mode）

> 默认模式：遇到问题主动搜索答案，不等用户指示，持续工作直到章节完成。

### 核心原则

```
遇到判断题 → 先搜索 → 再决定 → 不停止
```

### 决策规则

| 问题类型 | 自主处理方式 | 停止条件 |
|----------|--------------|----------|
| 这段文字该删除吗？ | 搜索"计划书章节写作规范"找标准 | 无 |
| 这个数据可信吗？ | 搜索多个来源交叉验证 | 多个来源都找不到 |
| 竞品分析完整吗？ | 搜索主要竞品官网补充 | 竞品数≥3 |
| 政策文件够新吗？ | 搜索最新政策文件 | 找到近1年内文件 |
| 措辞是否得当？ | 搜索同类计划书对照 | 无 |
| 逻辑是否通顺？ | 搜索"计划书写作逻辑检查清单" | 无 |

### 自主Research触发

遇到以下情况，立即自动触发 WebSearch：

```
□ 数据陈旧（超过2年）→ 搜索最新数据
□ 论证单薄（只有1个来源）→ 补充2-3个来源
□ 竞品数量 < 3 → 深挖补充
□ 政策引用非最新 → 更新最新版本
□ 遇到不确定表述 → 搜索确认
```

### 写作自检清单（边写边检）

每写完一段，立即自检：

```
- [ ] 数据有来源吗？  → 没有？搜索！
- [ ] 论证有漏洞吗？ → 有？补充！
- [ ] 措辞太绝对吗？ → 是？改！
- [ ] 与主档冲突吗？ → 冲突？以主档为准
- [ ] 重复内容吗？   → 重复？合并或删除
```

### 停止条件（真正需要用户的）

只有以下情况才停止，等用户确认：

```
□ TAM/SAM/SOM 完全无法找到任何数据
□ 创始人/团队成员信息完全空白
□ 商业模式完全不清楚
□ 用户明确说"停"
```

### 启动自主模式

```
说"持续工作"或"不用问我，直接做"
```

## PUA 动能集成

> PUA Skill 让写作过程"穷尽一切才允许放弃"，适用于 Research 不足、写作卡壳、Review 不严的场景。
> PUA Skill 位置：`/Users/magnus/.claude/skills/pua/skills/pua/SKILL.md`

### 何时激活 PUA

| 写作阶段 | 激活条件 | PUA 做什么 |
|----------|----------|------------|
| **Research** | 搜索结果 < 3条 | 继续搜索，不停止 |
| **初稿** | 连续2次修改后仍不够好 | 升级味道，换角度重写 |
| **Review** | 自己检查自己写的 | 用 PUA 挑剔视角审视 |

### 触发方式

```
/pua                              # 通用 PUA 激活
/pua:bytedance                   # 切换字节味（坦诚直接）
/pua 写作模式                     # 写作场景 PUA
"你搜索了但没找到足够数据"         # 自然语言触发
```

### PUA 自检清单（写作场景）

- [ ] 市场数据有2个以上独立来源吗？
- [ ] 竞品分析覆盖了主要玩家吗？
- [ ] 政策文件是最新的吗？（近1年内）
- [ ] 财务预测有合理假设支撑吗？
- [ ] 团队介绍有具体事例吗？
- [ ] 社会价值有量化指标吗？

**详见**：`references/pua-integration.md`

## 工作流v3.1（六阶段）

### 阶段0：建立项目主档
**输入**：用户项目基础信息
**输出**：Project Master（唯一信息源，状态标注完整）
**规范**：project-master.md

### 阶段1：Research补证据
**输出**：证据池（数据/政策/竞品/案例，不进正文）
**规范**：research-rules.md
**注意**：只补公开信息，不补私有事实
**触发**：主编判断是否需要WebSearch

### 阶段2：分析稿模式
**输出**：结构化版本（便于Review）
- 章节结构/关键判断/数据点/缺失项/可视化建议
**规范**：chapter-depth-guide.md（各章维度清单）

### 阶段3：成稿模式
**输出**：正式比赛文书
- 连续正文/多维论证/排除法/克制文风
**规范**：long-form-writing.md（5层论证/禁用词/过渡规范）

### 阶段4：Review与修订
**输出**：修订稿
- 主编协调交叉review，生成修订稿
**规范**：editor-in-chief.md

### 阶段5：统稿与可视化输出
**输出**：定稿 + 可视化图表
- 术语统一/口径统一/文风统一
- 根据章节需求决定可视化方案
**规范**：editor-in-chief.md + chart-style.md + html-prompt.md

## 两阶段输出流程（默认）

当用户说「第X章全部输出」时，按以下两阶段执行：

### 阶段一：正文先行
1. 读取项目配置文件 `.project-config.md`
2. 输出本章成稿正文，正文中用占位符标注图位：`图4-1【待生成】：xxx`
3. 同时输出可视化清单，标注每张图的优先级：
   - **必做**：没有它正文明显变弱
   - **建议做**：有了更好，但没它也能交
   - **可选**：主要用于答辩增强
4. 等待用户确认可视化清单

### 阶段二：批量生成
5. 用户确认后，一次性生成全部图表/HTML
6. 输出最终汇总包：
   - 正文终稿（含实际图号）
   - 图表文件清单
   - 图号与插入位置
   - 修订说明/缺失项说明

### 核心原则
- 正文逻辑先于图表生成
- 图表必须服务正文，不允许脱离正文单独堆图
- 如果某张图不如文字清晰，保留文字，不强制生成
