# AGENTS.md — working inside this repo

Reference for an agent **editing ns-ui itself**. Two other documents may be the one you want:

- Consuming a component in some other project → `https://design.helpmarq.com/llms.txt`, or the
  README.
- Setup, the add-a-component walkthrough, the token rule, and how to open a PR → `CONTRIBUTING.md`.
  That is the shared ground for humans and agents, and it is shorter.

What follows is the detail `CONTRIBUTING.md` deliberately leaves out: the `autoplay`, `useWhen` and
`gate` descriptor schemas, how prop signatures are extracted for `llms.txt`, and the constraints in
the preview driver that are easy to regress. Read the section you need, not the whole file.

## Structure

Each component is a self-contained folder: `registry/{core,loud}/<name>/` with:

- `component.tsx` — the actual component. `"use client"`, zero or minimal deps, tokens not hex.
- `demo.tsx` — the preview render used by `/preview/<name>` and the screenshot verifier.
- `meta.json` — the single source of truth: `name`, `title`, `description`, `collection`, `tags`,
  `instruction` (a rich paragraph describing behavior — read by `scripts/build-llms.ts`), `dependencies`,
  the optional site-only `autoplay` descriptor (see below) that makes the landing-page card
  demonstrate itself, and the optional site-only `useWhen` override (see below) for llms.txt's
  "use when" line.
- `screenshots/` — generated by `npm run verify`, not hand-authored.

`core` = Geist-dark restraint (169 components). `loud` = deliberately flashy showcase (28). Collection
is decided at creation time and drives folder placement, not a runtime flag.

## meta.json is the source of truth — never hand-edit generated files

`registry.json` (root) and `public/r/<name>.json` are generated from `meta.json` sidecars by
`npm run registry:build` (`scripts/build-registry.ts`). `public/llms.txt` and `public/llms-full.txt`
are generated the same way by `scripts/build-llms.ts` (chained into the same `registry:build` script).

Never hand-edit `registry.json`, anything under `public/r/`, or `public/llms*.txt` — edits will be
silently overwritten on the next build. If something in the generated output is wrong, fix
`meta.json` (or the component source, for prop signatures) and rebuild.

`public/r/` is gitignored — it's regenerated at build time (locally and on Vercel). `public/llms.txt`
/ `public/llms-full.txt` are NOT gitignored; they're small enough to commit, and get regenerated on
every build anyway so a stale commit self-heals on the next deploy.

## Autoplay — how a card demonstrates itself

Landing-page cards are iframes onto `/preview/<name>?embed=1&autoplay=1`, scaled down and
pointer-events:none. Most of the registry only wakes on input, so without help three quarters of
the grid showed a still frame (measured: 28 components at exactly 0.00% pixel change at rest).

A component declares **what kind of input demonstrates it** under an optional `autoplay` key in its
`meta.json`, and one shared driver (`app/preview/[name]/autoplay-driver.tsx`) synthesises that
input. There are no per-component animations — if a component needs something the five modes below
can't express, extend the driver, don't special-case the component.

**Where it runs:** only when *both* `embed=1` and `autoplay=1` are present. `/preview/<name>` with
no params is the honest reference — fully interactive, zero synthetic input — and must stay that
way. No descriptor ⇒ nothing runs (still frame, never a crash). `prefers-reduced-motion: reduce`
⇒ nothing runs.

**Rebuild after editing:** the descriptors are collected into `lib/autoplay.generated.json` by
`scripts/build-autoplay.ts`. Editing `meta.json` alone changes nothing on screen — run
`npm run autoplay:build` (or `npm run registry:build`, which chains it). A malformed descriptor
fails that script loudly rather than shipping.

Autoplay is **site-only** metadata: `build-registry.ts` and `build-llms.ts` read named meta fields,
so the key never reaches `registry.json`, `public/r/*.json` or `llms*.txt`. Keep it that way — it
describes the card, not the component's API, and a consumer must never see it as a prop.

### Descriptor schema

```jsonc
"autoplay": {
  "mode": "pointer-path" | "scroll" | "press" | "drag" | "type" | "none",  // required
  "period": 4000,   // ms for one full cycle including its rest beat. default 4000, min 400
  "delay": 600,     // ms after mount before the first cycle. default 600
  "target": "button" // CSS selector, queried inside the demo root. see per-mode meaning below
}
```

`target` never throws: matching nothing (or omitting it) falls back to the demo root. Coordinates
are normalized to the resolved box, `[0,0]` = its top-left. Absent key, or `"mode": "none"`, means
"genuinely ambient, needs nothing" — no driver mounts.
