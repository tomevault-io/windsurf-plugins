# Architecture Rules

This document defines the architectural invariants that all future models and contributions must respect.

## Project Layout

```
src/nobg/
├── __init__.py              # Public API exports (all model classes + AutoModel)
├── auto.py                  # AutoModel factory (tag-based dispatch)
├── mixin.py                 # Revised_Mixin (PyTorchModelHubMixin + Onnx_Mixin)
│                            # + Onnx_Mixin / OnnxModel (see ONNX Export)
├── utils.py                 # set_doc + model_card_template() + the shared
│                            # cutout() / post_process_alpha_matting() / predict()
└── <model_name>/
    ├── __init__.py
    ├── image_processing_<model_name>.py   # Processor (see Image Processors)
    └── modeling_<model_name>.py   # Config dataclass + model class
tests/
├── test_<model_name>.py     # One test file per model (one TestClass per model)
└── test_mixin.py            # Shared mixin behaviour (the ONNX round trip)
```

Each model lives in its own subdirectory under `src/nobg/`. The module must be named `modeling_<name>.py`.

## Configuration: Dataclass-Only Parameters

All model hyperparameters **must** be defined in a `@dataclass` named `<ModelName>Config`:

```python
@dataclass
class ExampleConfig:
    hidden_size: int = 256
    num_layers: int = 4
```

Rules:
- Every field must have a default value (the model must be instantiable with no arguments).
- For config dataclass fields, only use primitive types (`int`, `float`, `str`, `bool`) and simple containers (`list`, `tuple`) as field types.
- The config dataclass is the single source of truth for all architectural parameters.
- Config is serialized to `config.json` by the HuggingFace Hub mixin — no custom serialization logic.

## Model Class Structure

Every model must inherit from both `nn.Module` and `Revised_Mixin`, passing Hub metadata as class kwargs:

```python
class MyModel(
    nn.Module,
    Revised_Mixin,
    library_name="nobg",
    repo_url="https://github.com/feyninc/nobg",
    tags=["nobg", "<model-tag>"],
    model_card_template=model_card_template(class_name="MyModel", default_repo="nobg/<model-tag>"),
):
```

Constructor contract:
- Signature: `def __init__(self, config: Optional[MyModelConfig] = None)`
- First line after `super().__init__()` must be `self.config = config or MyModelConfig()`
- All layer construction must derive dimensions from `self.config` fields — no magic numbers.

## Inheritance Chain

```
nn.Module + Revised_Mixin → ConcreteModel
                ↑
    PyTorchModelHubMixin (huggingface_hub) + Onnx_Mixin
```

- `Revised_Mixin` provides `push_to_hub()` with auto-prefixed `repo_id` and model card injection.
- Do **not** override `save_pretrained` or `from_pretrained` — these are handled by the Hub mixin.
- Do **not** introduce new base classes between `Revised_Mixin` and concrete models. Shared
  behaviour goes into a mixin that `Revised_Mixin` itself inherits (as `Onnx_Mixin` does), so
  every model picks it up without changing its own bases.

## Model Card Template

Every model must pass a `model_card_template` kwarg generated by `utils.model_card_template()`:

```python
model_card_template = model_card_template(
    class_name="MyModel", default_repo="nobg/my-model"
)
```

This generates a Jinja2 template with:
- YAML front-matter (`{{ card_data }}`) for Hub metadata
- Load instructions via `AutoModel` and the direct class
- Contribution link

Do not write custom model card templates — use the shared function.

## Tags and AutoModel Registration

Models self-declare tags in the class definition. The `tags` list must include:
1. `"nobg"` (required for all models in this library)
2. A unique model identifier tag (e.g., `"gpt2"`, `"ann"`) used for AutoModel dispatch

`auto.py` dispatches on these tags. When adding a new model:
1. Append a new `elif "<tag>" in tags` branch at the end of the existing dispatch chain in `AutoModel.from_pretrained()`, before any final `else` or `raise` clause.
2. Import the model class at the top of `auto.py`

## Public API (`__init__.py`)

Every model class must be exported from `src/nobg/__init__.py`. Users must be able to do:

```python
from nobg import MyModel, AutoModel
```

The processors and `OnnxModel` (the runtime wrapper `onnx_from_pretrained` returns) are
exported the same way. A model class is never imported from its `modeling_<name>` module in
user-facing docs; only its config dataclass is.

## Tests

Each model gets its own test file: `tests/test_<model_name>.py`, containing one `class Test<ModelName>`.

Required test coverage for every model:

| Test | Purpose |
|------|---------|
| `test_init_default_config` | Default config produces valid model |
| `test_init_custom_config` | Custom config is respected |
| `test_forward` | Output shape is correct |
| `test_forward_batch` | Batched input works |
| `test_save_pretrained` | Produces `model.safetensors` + `config.json` |
| `test_save_pretrained_config_content` | `config.json` matches config fields exactly |
| `test_from_pretrained_roundtrip` | Load reconstructs correct config and architecture |
| `test_weights_preserved_after_roundtrip` | Loaded model produces identical outputs |
