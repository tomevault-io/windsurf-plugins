## This project was generated from a template

It started as infrastructure and conventions, not as a product. Two consequences follow.

**Core vs app code.** Core is changed only to fix or extend the infrastructure itself, never to satisfy one feature:

```
frontend/src/lib/                                router, vue-store, validation, utilities
frontend/src/infrastructure/eventBus/            the event bus
frontend/src/infrastructure/entityRepo/          transports and queries (app-specific sets aside)
frontend/src/infrastructure/{wails,theme}/       environment adapters
frontend/src/application/handlers/               ErrorHandler, NotificationHandler, AppThemeHandler
frontend/src/application/services/{id,toast,menu}/   IdService, ToastService, MenuService
frontend/src/components/{app,base,common}/       shared components and base classes
core/  build/  + build configs                   Go side and packaging
```

Everything else is written per project.

**The demo domain is gone.** The template shipped an `item` domain that demonstrated every convention end to end; it was deleted the moment the project got a real one (Kubernetes). Do not reintroduce it and do not resurrect its files from the template — the rules below are the reference, not that code. The `Item*` names that appear in the examples of this document are illustrations of a shape, nothing that exists in the repository.

## Project structure

- `main.go` — Wails entry point: window, tray, the list of bound Go services.
- `core/` — Go backend (services bound into the frontend, tray, utils).
- `build/` — packaging assets per OS. **Generated** from `build/config.yml` by `wails3 task common:update:build-assets` — edit `config.yml`, not the outputs.
- `VERSION` — the version of the application, raised with every commit, and the trigger of a release. See **Versioning and releases**.
- `.github/` — the CI and release workflows, and the script that writes the version everywhere.
- `.githooks/` — git hooks kept in the repository; `wails3 task setup:hooks` points git at them.
- `frontend/` — Vue frontend (TypeScript). All frontend rules below apply inside this folder.
  - `frontend/bindings/` — generated by Wails3. **Never edit manually** — regenerate with `task bindings` when the Go API changes.
- `.ai/` — design documents this one points at. **`.ai/ui-ux.md` is binding for every screen, component and stylesheet**: layout, density, motion, tables, status, loading and empty states, keyboard, icons, and how far the interface follows Lens. Read the relevant section before writing markup. Where it and this document disagree, this document wins.

## Verification — no visual checks unless asked

**Never run the app to look at it.** Do not start the Wails app, a vite dev server, or any other server, and do not drive a browser, take screenshots, or otherwise inspect the UI visually — unless the repository owner explicitly asks for it in that request. Do not create launch configs (`.claude/launch.json`) or other scaffolding for such a run either.

Verify work the way this repository already supports:

- `go build ./core/... .`, `go vet ./core/...`
- `npm test` (Vitest), `npx vue-tsc --noEmit`, `npx vite build`, `npm run lint` — all from `frontend/`

`go build ./...` also compiles `build/ios`, which needs an iOS toolchain — use `go build ./core/... .`.

If a change has UI consequences these checks cannot confirm, **say so plainly in the summary** ("built and typechecked, not looked at") and offer to run the app — do not run it on your own initiative. Permission is per request: "run it" today is not "run it whenever".
