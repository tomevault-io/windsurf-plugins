## What ATHENA is

ATHENA is a fully offline, privacy-first voice assistant (no cloud, telemetry, or API keys; zero runtime Python) that chains speech-to-text → LLM → text-to-speech entirely in C++ on a single consumer GPU plus large system RAM. The pipeline:

- **STT + LLM**: `whisper-talk-llama` (a patched whisper.cpp `talk-llama`) captures the mic (SDL2), transcribes with Whisper `small.en`, and runs the **Qwen3.5-397B-A17B** MoE chat model *in-process* (its routed experts offloaded to system RAM via `--cpu-moe`). It also does Silero VAD, prosodic endpointing, emotion2vec emotion tagging, barge-in, and cross-session memory.
- **TTS**: `talk-llama` streams generated assistant sentences to a trigger file; the `orpheus-speak` daemon reads them, asks a local `llama-server` (hosting the **Orpheus-3B** GGUF) for SNAC audio tokens over HTTP/SSE, decodes them to PCM with the **SNAC 24 kHz ONNX** vocoder, and plays via `aplay`.

**Three processes run concurrently**, all started by `launch-athena-397b.sh`: `llama-server` (Orpheus TTS backend, port 8080), `orpheus-speak` (SNAC decoder/player), and `whisper-talk-llama` (STT+LLM, run in the foreground/blocking). `speak-daemon.sh` is **not** a launched process — it is only registered as `talk-llama`'s `-s` speak handler and stays dormant because the active path is `--stream-file` (see gotchas).

> Two LLMs run at once. `llama-server` on :8080 serves **only** Orpheus TTS. The conversational Qwen model runs **inside** `whisper-talk-llama`, not over HTTP.

## Model file layout note

All model files live **flat in `models/`**, including the five Qwen shards (`Qwen3.5-397B-A17B-UD-Q3_K_XL-0000{1..5}-of-00005.gguf`). `launch-athena-397b.sh:29` previously pointed `QWEN_MODEL` at a nonexistent `models/QWEN-3.5-397B/` subdirectory, which made the preflight loop (`launch-athena-397b.sh:636-638`) abort every launch (see the failed run in `athena.log` at 2026-06-30 14:44:26). That path has been corrected to `models/Qwen3.5-...-00001-of-00005.gguf`; if you relocate the shards into a subdir, update `QWEN_MODEL` to match.

## Repository layout (ground truth)

The repo root is `/home/user/ATHENA` **on the reference machine, but the tree is relocatable** (CHANGES.MD §25): `launch-athena-397b.sh` and `speak-daemon.sh` derive `ATHENA_DIR` from their own location at runtime and build every path from it, so the repo runs from any clone location. The two `.desktop` launchers are generated by `install.sh` from `*.desktop.in` templates. Sources and models live under the root; the README was reconciled to the real layout on 2026-07-02 (real paths, verified URLs, current flags — see CHANGES.MD §17).

- `launch-athena-397b.sh` — the orchestrator (~926 lines). The bash script *is* the supervisor; there is no supervisor binary.
- `Athena 397B.desktop` — GNOME launcher (filename contains a space). Real entry point for the user (though since §16 the launcher defaults the same env, so shell launches are equivalent).
- `orpheus/` — ATHENA's own TTS engine: `orpheus-speak.cpp` (~2400 lines), `CMakeLists.txt`, `snac24_dynamic_fp16.onnx`, `build/orpheus-speak`.
- `speak-daemon.sh` — legacy text bridge (dormant; see gotchas).
- `athena-gpu-monitor.sh`, `demo-rec-start.sh`, `demo-rec-stop.sh` — satellite scripts.
- `models/` — `orpheus-3b-0.1-ft-UD-Q4_K_XL.gguf`, `Qwen3.5-397B-A17B-UD-Q3_K_XL-0000{1..5}-of-00005.gguf` (5 shards, ~165 GB, flat in `models/`), `ggml-small.en.bin`, `ggml-silero-v6.2.0.bin`, `emotion2vec_plus_large.onnx`.
- `llama.cpp/`, `whisper.cpp/` — vendored upstreams, built from source in-tree.
- `onnxruntime-linux-x64-gpu_cuda12-1.27.0/` — prebuilt ONNX Runtime GPU (CUDA 12), **not** built. This is the real `ONNXRUNTIME_ROOT`.
- `athena-diag/` — per-run timestamped diagnostics dirs.
- `patches/talk-llama/` — **the source of truth for the FIVE ATHENA-custom files** copied into `whisper.cpp/examples/talk-llama/` before configuring: `talk-llama.cpp`, `athena_memory.h`, `silero-endpointer.h`, `silero-turn-state.h` (all `#include`d locally), and `CMakeLists.txt` (upstream + ONNX Runtime/`ATHENA_EMOTION_ORT` wiring + a conditional `llama-kv-cache-dsa.cpp` guard so the same file builds the pinned tree AND current master, whose newer llama sync ships the DeepSeek-Sparse-Attention source). Earlier docs said two files and "no CMake edit needed" — wrong on both counts; the CMakeLists and silero headers were always custom. If you edit the build-tree copies, sync them back to `patches/`.
- `CHANGES.MD` — running session-by-session log of code/config changes (live bug fixes, the Orpheus garble instrumentation, attempted-then-reverted experiments, and current binary build state). **Read it first** to learn what changed most recently and why.

There is **no test suite, lint, or CI** in this repo. Do not invent test commands.
