# Как здесь работать

Проект — народный русский перевод Guild Wars 2. Подробный порядок работы для
участников лежит в [README.md](README.md); здесь — то, что нужно держать в
голове с первой минуты.

## 1. Иерархия правок: батчи → bin → граф

**`dictionary.bin` руками не правим никогда.** Он собирается из батчей.

```
правим батчи (crowdsource/<категория>/<имя>.csv)
  -> python tools/dict_tool.py frombatches --batches-win --apply
  -> python tools/index.py build          # граф И реестр названий
```

Батч решает про строку три вещи, и все три обязан решать он, а не bin:

| что | откуда берётся | если не оттуда |
|---|---|---|
| ТЕКСТ | колонка `translate` | — |
| МЕСТО | [ROUTES.txt](ROUTES.txt), `tools/routes.py` | категорию не переназначить: правку некуда записать и нечем проверить в PR |
| СУЩЕСТВОВАНИЕ | строка есть в батче | запись из словаря не удалить никогда |

Место — это группа отключения, и до 2026-09-03 оно хранилось ТОЛЬКО в bin:
`frombatches` смотрела, где строка лежит сейчас, и клала правку туда же. Теперь
категорию даёт `ROUTES.txt` (хеш → категория, `tools/routes.py build|check|set`,
ручные решения — в `ROUTES_FIX.csv`), а `--prune` сносит из bin то, чего нет ни в
одном батче.

Пустая ячейка перевода — «ещё не переведено», а не «удалить»: такая строка
сохраняет то, что уже есть в bin. Удаляет только ОТСУТСТВИЕ строки в батчах.

Строку, которую держит слой `pn_*`, сборка кладёт в её категорию ПО-АНГЛИЙСКИ:
русскую форму подставляет слой, и только так работает выключатель имён. Это
правило сборки, а не разовый скрипт — перевод названия, вернувшийся в обычный
батч, гасится автоматически.

**Граф в сборке bin не участвует.** `dict_tool.py` не знает про `sync/index.db`
вовсе: bin собирается из батчей и предыдущего bin, а граф выводится ИЗ bin.
Обратной связи нет и быть не может — иначе кольцо. Реестр названий (`names.py`)
влияет на bin только через посредника: `names.py emit --write` выписывает
найденное в батчи `pn/*.csv`, и дальше они вливаются штатным путём.

`index.py build` с 2026-08-31 строит не только граф, но и реестр названий
(таблицы `name` и `route`) — отдельно `names.py scan` звать не нужно.

Причина в [README §«Порядок работы»](README.md#порядок-работы-батчи--источник-истины):
батчи в git, у них есть история и откат; bin весит больше сотни мегабайт, в git
не лежит и правится необратимо. Разъезд между ними не видит ни один линтер —
обе стороны сами по себе чисты.

Латиница имён внутри фраз возвращается `tools/namelatin.py` — но только там, где
в переводе стоит ДОСЛОВНАЯ форма из слоя. Косвенные падежи он не трогает: слой не
склоняет, «в Львиной Арке» стало бы «в Львиная Арка». Это работа очереди «имена в
косвенных падежах», её делают руками.

У каждой пишущей по bin команды есть парная по батчам (`canon` → `canonbatches`,
`typo` → `tools/typofix.py`, `combat.py apply` → `combat.py batches`,
`gw2s_import.py apply` → `gw2s_import.py batches`). Звать надо парную. Если
правка всё же легла в bin первой — довести её до батчей в тот же заход, иначе
следующая сборка её сотрёт.

Только в bin живут русские имена словарей (`dict_tool.py dictnames`). Слой имён
`pn_*` **исключением не является**: он заведён в батчи `crowdsource/pn/*.csv`, и
`frombatches` их вливает (`batch_files(with_pn=True)`). `pnadd`/`pnset` пишут мимо
этого пути — правкой слоя считать их нельзя, иначе запись останется вне git.

## 2. Обязательные гейты

| когда | что запустить | что должно получиться |
|---|---|---|
| перед сдачей батча | `python validate.py <файл>` | 0 ошибок |
| заливка переводов | `python tools/batch_tool.py fill <батч> <json>` | сам делает бэкап в `.batch_bak/` и сверяет плейсхолдеры и колонку english |
| после записи в bin | `python tools/charscan.py compare .dict_bak/<последний бэкап>` | по незатронутым классам **+0, регрессий 0** |
| после правки bin | дописать раздел в [DEFECTS.md](DEFECTS.md) | состояние и остаток по каждому классу |
| после сборки bin | `python tools/dict_tool.py orphans` | «вне батчей: обычных 0, слоя 0» |
| сдача батча | `batch_tool.py claim <батч> --who <ник>`, затем `python stats.py --mark-done` | ✅ в [CLAIMS.md](CLAIMS.md) |

`charscan compare` идёт минуты — это нормально, не прерывать.

## 3. Канон терминов — в этом порядке

1. [GLOSSARY.md](GLOSSARY.md);
2. **человеческий корпус** — батчи, у которых в CLAIMS.md в колонке «Кто взял»
   не написано «Автозаполнение». Машинные батчи каноном не являются;
3. вики;
4. своё решение — и сразу в GLOSSARY.md, чтобы стало прецедентом.

Для названий предметов: тип вещи берётся из `/v2/items` через
`tools/itemfacts.py` (Targe — щит, Greaves — сапоги), прецеденты людей —
через `tools/index.py proof`. Названия сетов брони — из человеческих батчей
гардероба `ui_003…ui_007`, а не из головы.

Всё, что игрок может пойти гуглить (персонажи, локации, предметы, облики,
умения, титулы, фракции), обязано лежать в слое `pn_*` — смысл слоя в
обратимости, а не в переводе.

Обратимость держится на ДВУХ свойствах названия, и оба проверяются реестром
`tools/names.py`: название заведено в `pn_*` (`names.py gap`) **и** общий словарь
не перевёл его внутри фразы (`names.py inline`). Одного первого мало: игрок гасит
слой, а в строке уже стоит кириллица. Раскладка классов по словарям — в
[NAMEMAP.md](NAMEMAP.md).
