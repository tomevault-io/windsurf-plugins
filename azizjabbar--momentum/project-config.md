# Momentum

Flutter habit tracker that measures **momentum** (0–100, how automatic a habit has become)
instead of streaks. Full product spec: `Momentum_Habit_Proposal.pdf`. Full build plan (formulas,
data model, screen-by-screen sequence): `C:\Users\AzizJabbarShiddiq\.claude\plans\misty-wobbling-minsky.md`.

v1 is offline-only, mobile-first (Android target), built via Chrome for fast iteration.

## Running

```
flutter run -d chrome --web-port=<port>
```
Use a fresh `--web-port` each run — Flutter doesn't reliably release the previous port fast
enough for back-to-back launches. There's no way to hot-reload a backgrounded `flutter run`
process in this environment, so after code changes, stop the old process and relaunch fresh
rather than expecting hot reload.

Android SDK (command-line tools only, no Android Studio) and a portable JDK 17 are installed at:
```
Android SDK: C:\Users\AzizJabbarShiddiq\AppData\Local\Android\Sdk
JDK:         C:\Users\AzizJabbarShiddiq\AppData\Local\Java\jdk-17.0.19+10
```
`JAVA_HOME`/`ANDROID_HOME`/`ANDROID_SDK_ROOT` are set persistently (via `setx`), but a shell
opened before that won't have them — export them manually in-session if a command can't find
`java` or the SDK:
```
export JAVA_HOME="C:\Users\AzizJabbarShiddiq\AppData\Local\Java\jdk-17.0.19+10"
export ANDROID_HOME="C:\Users\AzizJabbarShiddiq\AppData\Local\Android\Sdk"
```
To build an installable APK (no phone/emulator needed for this step):
```
flutter build apk --release
```
Output: `build/app/outputs/flutter-apk/app-release.apk`. No Android emulator is set up, so this
build is not yet verified running on a real device — still worth doing before a device is
available, since compilation itself catches a lot (see the desugaring note below, found this way).

## Conventions

- State management: Riverpod. Local storage: Hive (`hive_ce`).
- Momentum, stage, and history are **derived**, never stored directly — see the plan doc's
  "Momentum Engine" section. The `Habit` model stores only a sparse `dailyLog` (date → amount);
  everything else is computed by replaying the growth/decay formulas over it.
- `lib/theme/app_theme.dart` defines the color language: habits shift color as they mature
  (fragile → red, building → amber, stable → blue, automatic → green), via
  `AppTheme.colorForMomentum()`. Reuse this instead of introducing new stage colors.
- Cards use soft shadows (`AppTheme.softShadow`), not borders, except the red outline Flutter
  adds to at-risk ("Needs attention") habit cards.
- The app icon (Android + web) was generated by `test/tool/generate_icons.dart`, not drawn in an
  external tool — no image editor available in this environment. It's deliberately named without
  a `_test.dart` suffix so `flutter test` never runs it automatically; regenerate by running it
  explicitly (`flutter test test/tool/generate_icons.dart`) if the design ever changes.

## Known constraints

- Windows Developer Mode is unavailable on this machine (non-admin user), so the project has no
  `windows/`, `linux/`, or `macos/` platform folders — Flutter otherwise tries to symlink plugin
  code into those desktop runners, which fails without it. Don't run `flutter create` in a way
  that regenerates them.
- `flutter_local_notifications` broke the Chrome web build until `flutter_web_plugins: {sdk:
  flutter}` was added as an explicit dependency in `pubspec.yaml` (its generated
  `web_plugin_registrant.dart` needs it directly available, not just transitively). If a future
  plugin trips the same "Couldn't resolve package flutter_web_plugins" error, try this first.
- `NotificationService` (`lib/data/notification_service.dart`) approximates the local timezone
  as a fixed UTC offset (no DST, whole-hour only) since there's no device-timezone plugin
  installed — fine for this user's locale (WIB/WITA/WIT, all whole-hour), but revisit if reminder
  times drift once tested on a real Android device.
- `file_picker` is pinned to `>=12.0.0-beta.1 <13.0.0` (a pre-release), not the stable 3.0.4 pub
  would otherwise resolve to — stable `file_picker` needs `win32 ^5.9.0` while `share_plus` needs
  `win32 ^6.0.1`, and only the 12.x beta line raised its constraint to match. If a future
  `pub upgrade` fights this, that's why.
- Backup export/import (`lib/data/backup/`) is platform-split via conditional import: web
  (`backup_web.dart`) uses `dart:html` to trigger a browser download / file-picker upload; mobile
  (`backup_io.dart`) writes a temp file and hands it to `share_plus`'s share sheet for export, and
  uses `file_picker` for import. Neither path is verified on a real Android device yet.

  below Android 8) and the release build fails without it. Found via a real failed
  `flutter build apk --release` (see Status).
