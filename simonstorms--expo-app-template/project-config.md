# Expo App Template

Expo SDK 57 / React Native 0.86 / React 19 (React Compiler on). Dev-client, **CNG** project,
package manager is **bun**.

## Building & running the app, READ THIS FIRST

Native `ios/` and `android/` are **generated by prebuild and gitignored** (see `.gitignore`).
Never hand-edit them. Edit `app.json`, `app.config.js` or a config plugin in `plugins/`, then
rebuild.

### The golden rule

**Build the native app once, then iterate on JS with Metro. Do NOT rebuild for JS/UI/style
changes.** Rebuilding for a colour or layout tweak is the number one time-waster.

### Everyday work (99% of changes: JS, TS, styles, components)

The dev-client is already installed on the simulator or device from a previous build. Just run
Metro and reload:

```bash
bun run dev            # = expo start --dev-client
```

Then press `i`, or reopen the app on the device: it reconnects to Metro and hot-reloads.
**No rebuild.** Prefer pressing `i` over launching by custom scheme (`openurl`), which triggers the
iOS "Open?" consent prompt.

### First run, or after a NATIVE change

Rebuild native **only** when you change one of:

- a native dependency (added, removed or upgraded)
- `app.json` / `app.config.js` / anything in `plugins/`
- entitlements or `Info.plist` keys
- app icons or the splash asset
- the Expo SDK

```bash
bun run ios -- --device "iPhone 17 Pro"   # build + install + launch + Metro on ONE pinned sim
```

- **Always pass `--device "<exact simulator name>"`** for a simulator you already have. Bare
  `bun run ios` prompts and boots new simulators, and that is how you end up with a pile of them.
  Pick one simulator, pin it, and use it for everything.
- **Run prebuild explicitly after a config change.** `expo run:ios` skips prebuild when `ios/`
  already exists, so an `app.json`, plugin or icon change silently does not apply:
  ```bash
  bunx expo prebuild -p ios && bun run ios -- --device "iPhone 17 Pro"
  ```
- Native state weird? `bunx expo prebuild --clean && bun run ios -- --device "iPhone 17 Pro"`
- Force-drop Xcode caches: `bunx expo run:ios --no-build-cache`

### When the local Mac toolchain is broken, use EAS (don't fight it)

If Xcode or the simulators are broken (missing frameworks, corrupt runtime, full disk) or you need
a real-device build, build in the cloud and install the artifact:

```bash
eas build -p ios --profile development           # simulator dev-client (.app)
eas build -p ios --profile development-device    # physical iPhone dev-client
```

Then `bun run dev` for Metro. Profiles live in `eas.json` (`development`, `development-device`,
`preview`, `production`).

### What the simulator cannot show you

- **Liquid glass.** `expo-glass-effect` renders a solid frosted fallback on a simulator:
  `src/components/ui/glass.tsx` gates on `isLiquidGlassAvailable() && Device.isDevice`. Real glass
  needs iOS 26+ hardware.
- **RevenueCat.** `hasRevenueCat` in `src/constants/config.ts` requires `Device.isDevice`, so
  purchases, entitlements and the hosted paywall are inert on a simulator even with keys set. Use a
  `development-device` build plus a StoreKit config or a sandbox tester.

Everything else, including the whole onboarding flow, auth UI and the built-in paywall, runs on the
simulator.

## Environment hygiene (prevents the recurring mess)

- **Pin one simulator** and reuse it. Do not create new ones.
- **Xcode must be a full stable install.** `xcode-select -p` must point at
  `/Applications/Xcode.app/...`, not a beta or partial install. A partial Xcode with a missing
  `SimulatorKit.framework` or a corrupt iOS runtime breaks all simulator control. The fix needs a
  password, so run it yourself:
  ```bash
  sudo xcode-select -s /Applications/Xcode.app
  ```
- **One Metro per project.** Default port 8081. If another project holds it, stop that one, do not
  spawn a second bundler.
- **Health check when things feel off:** `bunx expo-doctor`
- **Cleanup:**
  ```bash
  xcrun simctl shutdown all          # stop every booted simulator
  xcrun simctl delete unavailable    # delete sims tied to broken/removed runtimes
  lsof -ti:8081 | xargs kill -9      # free the Metro port
  ```

## Common build failures, and their fixes

- **`pod install` crashes with `Unicode Normalization not appropriate for ASCII-8BIT`, or
  "CocoaPods requires your terminal to be using UTF-8".** The shell locale is not UTF-8, which
  breaks CocoaPods on Ruby 4.x. Always build with UTF-8:
  ```bash
  export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8
  ```
  Put it in your shell profile so every build inherits it.
- **`Build input file cannot be found: .../ReactCodegen/…-generated.mm` (xcodebuild error 65).**
  Generated codegen is missing or stale, for example after deleting `ios/build` or after building
  with a different DerivedData path. Regenerate:
  ```bash
  LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 bunx expo prebuild --clean -p ios && bun run ios -- --device "iPhone 17 Pro"
  ```
- **Do not run a manual `xcodebuild -derivedDataPath ...` alongside `expo run:ios`.** Mixing
  DerivedData paths is what strands the codegen outputs. Let `expo run:ios` own the build.
