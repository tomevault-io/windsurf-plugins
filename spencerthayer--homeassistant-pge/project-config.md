## Learned User Preferences

- Prefer unattended Home Assistant operation via stored PGE email/password; no HITL bearer-token handoff and no MFA support (MFA accounts are unsupported). Treat portal access tokens as short-lived: re-login may be required nearly every sync interval, including mid-sync renewal. Respect Cognito password-login rate limits—back off instead of hammering InitiateAuth so accounts are not throttled or banned.
- Auth/sync failures must soft-fail: keep last-known sensors and recorder history; never blank the panel or purge downloaded usage/billing because renew failed. Persist tip intervals plus account/programs/tracker snapshots in Store and rehydrate them before the first poll so a failed boot poll cannot leave sensors at `unknown` while logs claim retained data. Long-running backfill must self-heal on stall (progress watchdog / stuck-task recovery) so sync_status cannot stay backfilling indefinitely without a HA restart.
- Prefer Cursor Browser (`cursor-ide-browser`) for live HA UAT with `./scripts/start.sh`/`./scripts/stop.sh`; reuse the existing live HA process—do not spawn a second/ad-hoc instance when one is already running. Custom-component Python changes need a full HA process restart (config-entry reload is not enough). After every substantive code or frontend change, confirm the affected surface (usually `/pge`) reflects the change and data loads correctly—blank, stale shells, or unexpected `unavailable` count as failure and require `./scripts/stop.sh` then `./scripts/start.sh` plus hard-refresh before calling the work done. When recent usage looks missing, Browser-check portlandgeneral.com My Energy Use (hourly) against HA `latest_available_interval` before treating a ~01:00 Pacific tip as overnight lag. Panel Sync status must reach complete (no failed backfill days) before UAT is done. Plans should embed Browser UAT checkpoints at code-review points (verify at `/config/integrations/integration/pge_energy`) and use the `.cursor/.ralph` loop for continuity, stopping only for HITL UAT confirmation before marking complete.
- Prefer the continual-delivery plan under `.cursor/plans/` as the source of truth (`instruct.md` is legacy); do not edit `.cursor/plans/` unless explicitly asked. Polling interval UI is a number plus a minutes/hours/days dropdown (default every 4 hours) plus a configurable Pacific sync clock that anchors the hour/day grid (default 12:00 AM → 12am/4am/8am/noon/4pm/8pm), with no static “minutes” suffix on the number field.
- Prefer credentials-only setup (email/password + account number per entry); source naming includes the account number (e.g. `PGE <accountnum>`); locally bundled PGE logo; options UI with password reveal; account number read-only after setup. Same login may own multiple entries with different account numbers. Prefer no personal account details hardcoded outside `.env` (which is intended to be removed); never commit secrets.
- Prefer tiered full-history sync into HA (hourly, then daily/monthly as available), with user-controllable sync frequency and history depth in settings, plus a manual force-sync path: a start modal that reuses saved sync settings, then a dedicated progress page (not just a popup) with real-time stats, ETA, and a progress bar. Use stock Home Assistant Energy (`/energy`) and native energy cards for consumption, cost, and PGE outdoor temperature; do not depend on third-party energy chart addons.
