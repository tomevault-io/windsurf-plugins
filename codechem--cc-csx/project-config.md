## Project Overview

CC.CSX is a C# HTML generation library that allows developers to create HTML declaratively using pure C# code (JSX-like / Hiccup-like). Seven NuGet packages live in this repo:

- **CC.CSX** (`src/CC.CSX/`): Core library — HTML element/attribute factories and rendering
- **CC.CSX.Web** (`src/CC.CSX.Web/`): ASP.NET Core integration — `HtmlResult` (implements `IResult`, `IActionResult`, `IEndpointMetadataProvider`)
- **CC.CSX.Htmx** (`src/CC.CSX.Htmx/`): HTMX attribute extensions (`hxPost`, `hxGet`, `target`, …) and `HtmxImports`. Depends only on CC.CSX (not CC.CSX.Web), so it loads in browser-wasm too
- **CC.CSX.Css** (`src/CC.CSX.Css/`): Strongly typed CSS sidecar — `CssClass` (incl. virtual/higher-order composed classes), `CssDeclaration` + lowercase `CssProperties` factories, `CssUnits` (`8.px()`), `CssBundle`/`CssImports`. Ships the `src/CC.CSX.Css.Generator/` source generator (netstandard2.0) which turns `.css` files registered as `AdditionalFiles` into typed members: `Css.<FileName>.<className>` constants, a baked-in `Source` const and a `Bundle`. Convention: elements are PascalCase, styles/classes are lowercase. Plain strings keep working everywhere (`CssClass` ⇄ `string` implicit conversions). Generation chain (regenerate, don't hand-edit): `eng/gen-css-property-keys.py` (MDN data → `CssPropertyKeys.cs`, keeps legacy/at-rule entries) then `eng/gen-css-properties.py` (`CssPropertyKeys.cs` → `CssProperties.cs`, skips at-rules). See `samples/Web` for end-to-end usage and `tests/CC.CSX.Css.Tests` for behavior.
- **CC.CSX.Browser** (`src/CC.CSX.Browser/`): Client-side rendering in .NET WASM (no Blazor) — `BrowserApp.MountAsync("#app", View)` renders the view and morphs the DOM in place (focus/caret survive; morph + delegated capture-phase listeners live in `ccsx-browser.js`, shipped as an embedded resource imported via a `data:` URL ES module, so host apps need no asset wiring). Events: `using static CC.CSX.Browser.HtmlEvents` gives delegate overloads `onClick(Action)`/`onClick(Action<DomEvent>)`/async variants for all 33 events (`HtmlEvents.g.cs`, generated by `eng/gen-browser-events.py` from `HtmlAttributeKeys_Events.cs` — regenerate, don't hand-edit), generic `on("pointerdown", …)`, plus htmx-style stable named actions: `htAction("counter/reset")` + `BrowserApp.Map("counter/reset", handler)`. Handlers render as `data-ht-on-<event>` attributes — numeric ids are per-render (delegates), strings are stable action names. Also intercepts CC.CSX.Htmx `hx-get/post/put/patch/delete` markup client-side: `BrowserApp.MapGet/MapPost/…("/todos/{id}", req => …)` routes (Minimal-API-style templates, `HxRequest` carries merged query/form/path params), with hx-target (`this`/`closest`/`find`/selector) and hx-swap (`innerHTML`/`outerHTML`/`before*`/`after*`/`delete`/`none`/`morph`) subsets — same markup works server-side with htmx.js or in-browser with no server. `BrowserApp.StartAsync(selector)` runs hx routing over static DOM without mounting a view. Caveat: delegate ids inside hx-swapped fragments die on the next full `Refresh` — prefer hx/`htAction` attributes inside route responses. See `samples/BrowserSample` (run with `make run.browser`) and `tests/CC.CSX.Browser.Tests`.
- **CC.CSX.Components** (`src/CC.CSX.Components/`): Ready-to-use, themeable UI components (`UI.Button`/`Card`/`Alert`/`Badge`/`CardTitle`, import `using static CC.CSX.Components.UI`). Visuals come from a swappable `IComponentTheme` (ambient `Theme.Current`, scoped `Theme.With(...)`); the default `DaisyUiTheme` emits daisyUI markup. `Variant`/`Size` enums are semantic (not daisyUI-specific) so a different theme reskins everything — this is also the seam a future non-web backend would implement. `ComponentBuilder` merges the theme's classes with any caller-supplied `class` attribute into one (HtmlNode does not dedupe attributes). Theme classes are returned as **literals** (not interpolated) so a Tailwind build can find them; the set `DaisyUiTheme` can emit is also shipped as a safelist (`daisyui.safelist.css`, packed under `tailwind/`) for NuGet consumers who can't scan package source. Production CSS = a real Tailwind+daisyUI build (see `samples/ComponentsSample`); the daisyUI CDN is dev-only (`DaisyImports.Cdn()`). See `tests/CC.CSX.Components.Tests`.
- **CC.CSX.Css.Tailwind** (`src/CC.CSX.Css.Tailwind/`): Strongly typed Tailwind utilities — `Tw` static class with ~2900 default-theme `CssClass` constants (`Tw.Classes.g.cs`, generated by `eng/gen-tailwind-classes.py` — regenerate, don't hand-edit), variant combinator methods (`hover`, `focus`, `dark`, `sm`–`xl2`, generic `variant`), `neg`/`important`, and arbitrary-value methods (`mt("17px")` → `mt-[17px]`). Caution: `using static Tw` alongside `using static CssProperties` collides on names like `gap`/`flex` — use qualified `Tw.*` in files that import both.
