# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An Android app (Kotlin, Compose, Room) that records how long each pair of headphones stays
connected, forever and locally, so lifetime hours per *physical pair* can be trusted years later.
`README.md` is the product-level description and is accurate — read it for the two tracking modes,
the accuracy rules and the flavor split before changing anything in those areas.

## Commands

The nix dev shell pins the exact JDK 21, Gradle 9 and Android SDK (platform `android-37.0`,
build-tools `37.0.0`):

```sh
nix develop            # or: direnv allow
```

Every Gradle task is flavor-qualified — there is no plain `assembleDebug`:

```sh
./gradlew assembleClassicDebug          # sideload build
./gradlew assemblePlayDebug             # store build
./gradlew installClassicDebug
./gradlew bundlePlayRelease             # Play Console AAB

# what CI runs, per flavor (matrix over classic/play)
./gradlew lintClassicReleaseTest createClassicReleaseTestUnitTestCoverageReport \
          assembleClassicDebug assembleClassicRelease

# a single test class or method
./gradlew testClassicReleaseTestUnitTest --tests '*SessionRepositoryTest'
./gradlew testClassicReleaseTestUnitTest --tests '*SessionRepositoryTest.a reconcile racing*'

# tests + JaCoCo report, then the same summary CI prints
./gradlew createClassicReleaseTestUnitTestCoverageReport
python3 .github/scripts/coverage-summary.py \
    app/build/reports/coverage/test/classic/releaseTest/report.xml classic
```

Debug builds carry `applicationIdSuffix = ".debug"`, so a debug and a release install coexist.

### Lint is a hard gate

`checkAllWarnings`, `warningsAsErrors` and `abortOnError` are all on, and `checkTestSources`
extends that to `src/test` and `src/androidTest`. Both belong to the `releaseTest` build type, so
`lint<Flavor>ReleaseTest` sees them — `lint<Flavor>Debug` still runs but has no test sources to
check. There is no baseline file: a baseline hides a finding instead of deciding about it. A
warning — including checks lint ships disabled — fails the build like an error.

The only two ways to land a finding are to fix it or turn the check off in `app/lint.xml` **with
a reason**. The checks off cannot hold here: `NewerVersionAvailable`/`GradleDependency` (they hit
the network, and versions are pinned on purpose), `DuplicateStrings` (77 translations of ~150
strings collide legitimately), `ConvertToWebp` *scoped to `res/drawable-nodpi`*, where the widget
previews are generated by a tool that writes only PNG, and `NewApi`/`InlinedApi` *scoped to
`src/test`* only, because Robolectric runs against the compile SDK rather than the minSdk 26
floor those checks enforce.

One consequence: a few members are `internal` rather than `private` purely so a nested class can
reach them without a synthetic accessor, with a comment saying so.

The Kotlin compiler is held to the same standard: `allWarningsAsErrors` fails the build on a
deprecation. The usual trigger is a Dependabot bump, and failing that PR is intended. Tests use
`androidx.compose.ui.test.junit4.v2.createComposeRule` for the same reason; its v2 rule dispatches
with `StandardTestDispatcher` rather than `UnconfinedTestDispatcher`, and the Roborazzi listing
captures were re-recorded and eyeballed against before the switch landed.

### Coverage

`enableUnitTestCoverage = true` on the `releaseTest` build type (see Testing) gives AGP a
`create<Variant>UnitTestCoverageReport` task; the report lands in
`app/build/reports/coverage/test/<flavor>/releaseTest/` and CI uploads it and prints the summary
table into the job summary.

**It is a gate, not just a report.** CI passes `--min-instruction=95 --min-line=98
--min-branch=70` and fails below any, printing the miss budget rather than the percentage. Line
sat at 99 until minSdk 26 made it uncollectable: on `classic`, `Distribution.HAS_SPECIAL_USE_FGS`
is compile-time true, so `TrackingController.detailedTrackingSupported()` short-circuits before
its Bluetooth-permission check, making `SettingsScreen`'s "detailed tracking unavailable" notice
unreachable — that path exists only for `play`, where API 34+ needs the permission since the
flavor declares no `specialUse` foreground-service type. Below API 26 an unfixed-service install
used to reach the same lines another way; raising the floor deleted that route, so this is dead
code on one flavor, not a testing gap. The shared floor costs the flavor that didn't lose lines:
`play` runs at 99.1 but is held only to 98, so a real regression there down to that line would
pass unnoticed.

Branch is gated looser — suite at 77.0, floor 70 — because the counter moves when a composable
gains a parameter rather than when testing gets worse (see below), so a tighter floor would fail
ordinary UI work as a regression. 70 leaves ~80 missed branches of headroom, enough that a breach
means something real. Method and class are ungated: at ~95% they are six classes from a 90 floor,
close enough that ordinary work would trip them.
